# AI Agent：使用 M4 模型训练自己的 LUT

[English](AGENT_TRAINING.en.md) · [训练代码与素材入口](../../training/README.md) · [模型合同](../../training/MODEL.md) · [大色卡](../../training/DATASETS.md) · [相机 JSON 格式](../../methods/08-custom-lut/FORMAT.md)

使用冻结的 M4 电脑模型，反复改变滤镜 JSON 并模拟机内输出，拟合同源目标图。在已覆盖范围内，不需要每轮把 JSON 导入机身重新拍摄。本文面向能读取文件、编写适配代码及运行 Python 的 AI Agent，不要求用户手工操作训练软件。

## 给 Agent 的指令

> 请读取本指南、training/AGENTS.md、模型及数据清单，使用冻结的 M4 模型拟合我的滤镜。先运行 doctor，核对实际可用文件；大色卡必须使用指定 Sony ARW，富士 RAF 只用于生成目标。保持拍摄 WB 和原始曝光，电脑不增加镜头校正。优先优化1215项signed7网格，保护真实材质、肤色阴影、中性暗部及颜色连续性；必要时测量Gamma／矩阵／基础系数响应再联合搜索。不要为目标风格重新训练相机响应模型。请自主建立配对、场景角色、采样和固定保护参考，用实际导出整数JSON的正式渲染复核，并保留可继续运行的代码与记录。无需每轮要求我导入相机重拍。只有确实缺少目标或模型范围不足时，集中说明需要补充什么。

## 三类工作分别记录

| 工作 | 输入 → 输出 | 使用方式 |
|---|---|---|
| M4响应模型标定 | 已知JSON的RAW／机内JPEG → 相机模型 | 本项目已有冻结模型，新风格通常复用 |
| 滤镜拟合 | 同源RAW／目标＋冻结模型 → 原生JSON | 在电脑连续迭代，本文主流程 |
| 实机确认 | 最终候选＋新场景照片 → 机内验收 | 可集中进行，不插入每轮优化 |

模型复现相机的误差，与滤镜匹配富士目标的误差不能互换。大色卡合成输入不等于物理M4跨传感器验证，离线合格不自动写成机内实拍通过。

## 输入及组织

先准备[模型素材](../../training/MODEL.md)、合法的原生种子JSON和目标。12款现有富士风格可复用素材中的目标采样；新风格需要同一份RAW生成的目标图或可复现处理配方。不对应同一RAW的参考图只作风格参考。

普通照片可以训练，无需专业色卡。建议覆盖肤色及其阴影、白色、蓝色、植物、深色材料和平滑渐变。把同一RAW的多个导出、连拍及同场景裁切归为同一场景组，按组划分训练、开发和最终测试；不能随机分像素制造“未见场景”。

优先16位sRGB TIFF、原尺寸和方向。登记实际软件、风格、WB、曝光、输出空间和裁切；侧车可选，用户确认的设置与独立核对的设置分别标记。复现本项目富士目标使用RFCEX，不改成Lightroom＋DCP。不同软件的色温显示不能用于强行重定白点。

当前大色卡的CC已换成受控as-shot目标；其余11款历史目标的WB尚未逐款独立核验，详见[数据状态](../../training/DATASETS.md)。保留真实状态和哈希，不用更换目标产生的降分冒充参数改善。

## 执行流程

### 1. 核对依赖和当前范围

从仓库的training目录和独立素材附件开始，不要求重建维护者的研究目录。`run.py doctor`核对权重、桥接、原生编解码器、Sony参考文件及上游身份。参考命令见[训练入口](../../training/README.md)。依赖缺失时具体列出，不能仅凭方法文档声称已运行模型。

当前原生链为实际ARW的CFA／黑电平／拍摄WB → ITP／SSCS → JSON控制的原生系数、矩阵、Gamma和空间处理 → 冻结M4桥接及网格响应 → RGB16。Sony应用不需运行，相机不需连接。网格仍有经验标定部分；已测上下文以MODEL文档为准。

### 2. 固定基线、对应关系和保护集

为任务保存清单，记录输入与目标哈希、模型合同、种子、软件配方、采样单位、场景角色及验收条件。清单是Agent自己的任务记录，不是相机导入JSON；不要让用户为历史脚本手填旧P01～P21目录。

测种子对目标的ΔE00及RGB RMSE，并检查整图和阴影。几何配准只处理对应关系，不包含曝光／WB／直方图匹配。真实ROI保留各自多边形内的像素，不把非线性模型的输入替换为整块均值。完全剪切和低色度点保留数量、用途及掩膜，不静默删掉难点。

大色卡按清单的32px tile内部5像素均值读取，不能用设计RGB代替指定ARW。它提供99,372个配对色及灰阶／24色相轨道；仍是一份合成RAW，不能当作独立验证集。

### 3. 冻结模型，先拟合网格

保持相机模型及种子的原生参数不变，优化3×5×9×9共1215项signed7整数，范围−64～63。可以从相对种子±16的信赖域开始，多起点或逐步扩展；实际边界始终受相机格式和已测模型约束。拍照／预览网格按现有策略同步，不把两条原生参数链当作相同布局。

`fit_grid.propose`提供Adam／STE提案，`fit-chart`提供大色卡示例。默认1800步是预算示例，不是固定精度保证。训练损失联合平均／尾部ΔE00、中性暗部a*／b*／色度、肤色阴影、局部平滑及参数正则；真实场景保护必须由Agent按自己的配对补入。只对色卡合格的候选保留“色卡候选”标记。

### 4. 用实测响应扩大到联合整数搜索

网格难以进一步改善时，复用`native_family.py`的116个原生精选方向：Gamma12、矩阵96、基础系数8。它们绑在一起改变上下文／端点，不是完整独立参数族。原生变化必须重新渲染原生RGB；只改网格才复用相同前段。

分别测正／负一单位响应，保留不可用方向及原因，构造逐色误差和聚合指标的响应矩阵。用`integer_search.solve`的有符号MILP提出满足信赖域、总步长和真实photo/live余量的组合。线性预测只作提案，必须再用模型实际渲染，失败则缩小信赖域或测新响应。

保护参考应固定到任务开始时的逐色／聚合上限，或只向更好的已采用值收紧。最新严格方法只在参考外加一次1e-4容差，不能随轮次累计。MILP零步、已测方向失败不证明全局无解；连续分数不能当整数参数的成绩。

### 5. 正式导出与独立复核

从候选导出的JSON重新读取，运行`seal/encode/parse/compile_native`，使用正式129³表、32768分块、既定浮点顺序和RGB16内核。Node子集／小网络直接预测仅用于提案，不冒充完整表重放。

逐款报告平均ΔE00、P95、最大值、RGB RMSE；另外报告阴影与肤色阴影、中性L*／a*／b*／C*、有效色相轨道和真实RGB直方图。明度轴明确使用L*还是HSV V，色相偏移使用圆周最短有符号角。低色度、黑场及剪切掩膜必须明示。

Gamma按实际非均匀x坐标检查一阶单调性及二阶差分；胶片曲线可能含S形，不能为了图形好看就宣称二阶恒负。训练和正式渲染必须使用同一目标、模型及原生输入；更换目标／WB后的分数需重新建立基线。

已有历史140色色卡、多曝光／WB、材质和肤色资料可反复模拟作保护，不需每轮重拍。已参与选择的数据不叫盲测。没有通过全部固定保护的新参数就保留原件，并列出仍差的颜色与覆盖缺口。

## 交付及继续运行

交付原名滤镜JSON、模型与数据身份、任务清单、可重跑命令、连续／整数／正式复核分数和残差图。保存未采用候选与拒绝原因，最终测试用未参与本次拟合及选择的场景。源码与模型附件分别管理；照片、完整TIFF、输出数组、权重和候选不自动加入Git。

当前公开代码是供Agent复用的研究原语，不是已为每位用户的数据完成适配的桌面软件。新场景／新机型／未支持上下文需要补验证时，说明具体缺口并尽量集中采集；不要回到逐候选反复要求用户实拍的流程。
