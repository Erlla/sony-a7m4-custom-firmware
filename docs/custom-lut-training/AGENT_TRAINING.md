# 使用 AI Agent 拟合自己的 M4 滤镜

[English](AGENT_TRAINING.en.md) · [训练结果](README.md) · [相机 JSON 格式](../../methods/08-custom-lut/FORMAT.md)

用户提供原始 ARW 和希望得到的同源目标图，让能够读取本地文件、编写代码及运行 Python 的 AI Agent 按本文适配并训练。交付物是可导入相机的原生外观 JSON，以及可复现的评估记录；不要求桌面软件、安装包或通用训练界面。

本文是 Agent 的执行合同。现有训练代码含研究案例路径，需要 Agent 阅读源码后为新数据建立适配层。**阅读方法不能代替取得模型文件**：执行环境仍须具备已适配的 M4 模型、响应权重、原生编解码器及所需显影运行时。只有公开结果页面时，先完成资料整理并报告缺少的依赖，不得声称已经用 M4 模型训练。

## 用户给 Agent 的指令

把下面的指令和实际素材目录一起交给 Agent 即可：

> 请按《AI Agent 滤镜训练指南》使用现有 M4 模型拟合我的滤镜。先读取可用工作区的交接记录和当前模型合同，寻找已有工具与依赖。素材目录中保存原始 ARW、同一 ARW 的目标 TIFF，以及可选的机内直出 JPEG 和显影设置。普通照片可以使用，没有专业色卡。请自主完成数据配对、场景分组、区域采样、参数搜索、整数化、正式渲染复核和交付。默认冻结 M4 模型，先优化滤镜网格，保护肤色、阴影与颜色连续性；电脑不加镜头校正。只在确实缺少文件、配对关系或目标设置时集中询问。请把预测结果和机内实拍结果分别标明，保留可继续运行的脚本、任务清单和记录，不要求我每轮导入相机重拍。

## 先分清三件事

| 工作 | 输入和输出 | 本流程的处理 |
|---|---|---|
| 标定 M4 响应模型 | 已知参数的 ARW／机内 JPEG → 相机响应模型 | 复用已标定模型，不要求每位用户重拍探针 |
| 拟合用户滤镜 | ARW＋目标图＋M4 模型 → 原生外观 JSON | 本文的主要任务 |
| 机内验收 | 候选 JSON＋少量新拍照片 → 实际效果结论 | 离线完成后可集中进行，不插入每轮搜索 |

不要为一个新风格重新训练 M4 响应网络，也不要用普通 RGB 后期映射替换相机实际需要的参数后，宣称得到了可导入的 JSON。

## 输入要求

| 数据 | 是否必需 | Agent 应读取什么 |
|---|---|---|
| 模型与运行环境 | 执行前必需，维护者提供一次 | 模型合同及递归依赖、显影算子、响应权重、原生 JSON 编解码器、Python／CUDA 环境 |
| 合法的 M4 原生外观种子 JSON | 必需，可由维护者提供 | 相机格式、已有 Gamma／矩阵／基础系数、网格、默认菜单值与适用范围 |
| 原始 ARW | 必需 | 机型、RAW 格式、白平衡、ISO、曝光、尺寸和原生记录；不改写原件 |
| 同一 ARW 的目标图 | 直接图像拟合必需 | 优先 16 位 sRGB TIFF、原尺寸；明确色彩空间、方向、裁切及目标处理规则 |
| 同次机内直出 JPEG | 推荐 | 检查模型是否能复现该拍摄状态；记录当时外观、LUT 和微调，未知时不作已知参数真值 |
| 显影设置／配方 | 必需知道，文件可选 | 软件及版本、滤镜、WB、曝光补偿、输出空间等；没有侧车但用户已确认设置时，记录为用户确认 |
| DCP、cube、预设等源文件 | 有则保留 | 输入域、基础显影、使用的软件和设置；不能只凭扩展名断言可直接等价转换 |

目标可以来自用户自己的后期调色，也可以来自明确的软件风格。复现本项目富士模拟时，目标采用同源 ARW 转换 RAF 后的 **RAW FILE CONVERTER EX** 输出，不能悄悄换成 Lightroom＋DCP。这是该软件处理链的风格目标，不等于富士机身实拍真值。

有可复现的目标处理方法时，可以对已有 RAW 批量生成目标，多款滤镜共享同批 RAW。不必让用户为每款风格重新拍摄。

目标只有 JPEG 时也可做试用拟合，由 Agent 适配实际读图与色彩管理，注明压缩和位深限制。仅有不对应同一 RAW 的参考照片时，先作为风格参考，不把它冒充配对真值。

## 普通照片怎样使用

专业色卡不是必需品。普通照片建议覆盖人脸／肤色、植物、天空、蓝色物体、白色材料、深色材料及平滑明暗渐变，并覆盖用户真正会使用的曝光和白平衡。15～25 组训练／开发配对、另留 3～5 个未见场景，是起步建议，不是程序的固定门槛。只有少数照片时可做场景限定的试用版，但要如实标明覆盖范围。

同一张 RAW 的多个导出、连拍、同场景裁切图必须归入同一场景组。先按场景分训练、开发、最终测试，再取像素；不能随机拆像素来制造“独立验证”。最终测试只用于最终评估，若看结果后继续针对它调参，应将其改记为开发／回归数据，另留新测试场景。

为每张图建立实际的对应区域和语义标签：平坦颜色、肤色、肤色阴影、白色、蓝色、深阴影、渐变等。去除区域边缘、错位、遮挡以及无信息的完全剪切像素；保留剪切数量和代表性阴影／高光评估区域。不要照搬历史色卡的 140 个坐标或旧场景的肤色标签。

自然场景还应比较有对应关系的像素误差和渐变连续性，不能只取很大的 ROI 均值。原始直方图用于辅助检查，不可替代逐区域／像素的颜色对应关系。

## 执行顺序与完成条件

### 1. 读取工程并确认运行范围

先读可用工作区的交接记录，再读模型合同及其依赖。确认当前使用的后端和模型版本，不能依靠 README 历史段落猜默认值。当前明确算子路线为 `edit-explicit`，核心依赖关系是：

`ARW CFA → Sony Edit 明确原生前段 → M4 零网格桥接 → 已标定 signed7 网格响应 → 输出`

网格响应仍有经验模型部分，不能宣称完整硬件 ISP 逐位复刻。当前已接入的拍照 Gamma、端点选择、WB 和菜单状态有适用范围；新数据超出范围时，先报告具体不匹配，不能将未支持的状态默认为已支持。

完成条件：能明确指出模型文件、实际所需权重／算子、编解码器、种子和一组配对输入的位置。依赖缺失时只报告缺失项，不生成虚构训练分数。

### 2. 配对、色彩管理与几何对应

按实际 RAW 来源配对，不单靠文件名相似。核对尺寸、方向、色彩空间及显影设置；记录各组真实曝光和 WB。不同组可以有不同设置，不能强制把所有数据归一化到同一曝光／色温而改变训练目标。

电脑不额外应用镜头校正。历史机内补偿为自动／开启时原样记录，不能改写成“已关闭”。目标如已发生几何变形，应通过坐标映射或共同有效区建立对应，不能直接逐像素相减。几何配准不包含调色、曝光匹配、WB 匹配或直方图匹配。

完成条件：每个样本都有同源关系、场景组、角色和真实区域映射；无法对应的样本注明原因并不进入数值训练。

### 3. 先测起点，再求解新参数

用种子 JSON 预测目标数据，并分别记录：

- 模型对目标风格的误差：预测输出与同源目标图比较。
- 模型对机内输出的误差：仅在已知原生参数的 ARW／机内 JPEG 配对可用时测量。

两种误差不相减，也不能混用名称。先出一组整图和局部预览，检查采样、单位、颜色通道和阴影方向，再扩大训练。

缓存绑定 RAW、模型及实现、原生参数和几何信息。改变矩阵／Gamma／基础系数后应重建相关原生缓存；只改网格时才可复用相同的原生前段。不要因旧目录中有 `complete=true` 就跳过新任务。

### 4. 冻结 M4 模型，优化滤镜

默认先保持种子的 Gamma、矩阵、基础颜色系数、WB 增量和默认菜单值，优化 `3×5×9×9 = 1215` 个网格整数，范围 `−64～63`。照片与预览分支同步。可从相对种子 ±16 的信赖域开始，逐步扩大到现有标定支持的范围；不能靠突破相机格式范围解决误差。

损失函数至少联合以下项，并明确各项单位及权重：

- 对应区域／像素的 ΔE00，以及尾部误差，避免只降低平均值。
- 阴影、肤色阴影和白色材料的色偏惩罚。
- 平滑颜色路径、灰轴和明暗渐变的连续性保护。
- 相对起点的参数偏移和局部变化正则，减少无数据约束区域的异常。

从当前实现的两轮 Adam 搜索、每轮 1800 步开始可作工程起点；多起点、步数和参数权重由开发集决定。最后阶段使用整数前向／STE，并以实际整数结果筛选。它们不是保证精度的固定配方。

只有网格难以达标、且所需原生算子和参数响应已经支持时，才进一步联合 Gamma／矩阵／基础系数搜索；同步重算前段及缓存，分别量化连续解、约束和量化的损失。不要把旧“116 维精选”或更多自由度当成此次默认已经执行的内容。

### 5. 用约束筛选，再进行正式渲染

候选应同时改善目标误差，并保护开发场景、阴影、肤色阴影及输出连续性。现有参考保护阈值为组均值最多增加 0.015、P95 最多增加 0.04、最大值最多增加 0.08；逐条件均值最多增加 `max(0.05, 该条件基准均值×2%)`。这些是相对基准的小容差，不表示每个颜色都严格改善，也不表示最大误差已低于 3。

在任务开始时记录本次实际采用的约束。不能看到候选失败后放宽阈值冒充通过；若把开发之外的目标加入梯度，更新数据角色。没有通过的改进候选时保留种子，并报告主要残差和原因。

最终将整数参数写入真正的外观 JSON，使用已有 `seal/encode`、主机验证／编译，再**从导出的文件重新读取**，通过正式前向和输出内核渲染训练／开发样本及最终未见场景。不能只交连续张量的预测分数。网格单独训练时，核对未拟合的原生参数没有意外改变。

完成条件：实际导出的 JSON 能被主机解析、正式渲染结果符合约束，报告中有整数后和最终测试结果。文件合法、离线改善和相机实测通过是三个不同结论。

### 6. 交付并保留可继续运行的任务

交付一个普通文件夹，包含原始风格名称的 JSON、使用说明及评估入口。训练工作目录保留任务清单、适配脚本、运行配置、种子、依赖身份、日志和评估记录；原片、目标、缓存、权重仅保留在约定本地数据位置。

报告至少包含训练／开发／最终测试各自的平均 ΔE00、P95、最大值、RGB RMSE，注明按像素还是按 ROI 均值计分及权重；另列阴影、肤色阴影、白色和逐场景残差。RGB 使用 0～255 尺度时要明示。附 RGB 直方图、代表整图、局部阴影及平滑渐变对比。ROI 均值 RMSE 不能标成全图逐像素 RMSE，逐图 P95 的平均也不是合并 P95。

候选可以先以“离线验证”交付。需要机内验证时一次安排少量代表场景与基准对照，不让用户为每轮优化反复导入重拍；实际拍摄前不写“机内验收通过”。

## Agent 如何接入实际模型

本公开仓库提供[相机 JSON 合同](../../methods/08-custom-lut/FORMAT.md)、[固件集成说明](../../methods/08-custom-lut/IMPLEMENTATION.md)和[训练结果](README.md)。维护者的完整 M4 训练工作树、响应权重、显影常量和运行环境没有随这些方法文档分发。需要由维护者或用户提供可访问的依赖；不能把公开方法描述为已经可以单独运行的训练器。

| 需要的能力 | Agent 应确认的执行合同 |
|---|---|
| RAW 读取和原生前段 | 实际机型和 RAW 格式受支持；保留拍摄 WB／ISO，明确 Gamma、矩阵端点和菜单上下文 |
| 冻结的 M4 网格响应 | 输入域、网格布局和 signed7 范围已知；训练与正式渲染使用同一模型／版本 |
| 对应区域和像素 | 区域坐标、掩膜、几何映射及颜色空间明确；支持普通照片，不只支持固定色卡 |
| 求解器 | 能对滤镜参数求梯度或作数值搜索；按本任务的场景角色和损失计算 |
| 原生 JSON 编码与编译 | 使用真实格式校验和运行字段哈希；重新读取导出的文件验证 |
| 正式渲染与评估 | 对实际导出的参数执行完整输出路径，包含剪切和取整；提供未见场景结果 |

获得维护者的研究工作树时，Agent 可查找 `edit_explicit.py`、`explicit_training_data.py`、`explicit_grid_fit.py`、`run_refinement.py`、`export_candidates.py`、`replay_candidates.py` 等实现。上述名字是已有实现的定位线索，**不是本公开仓库保证存在的源码链接或通用 CLI**。先检查实际文件，再复用其算法。

在新任务中编写薄适配层，显式传入模型、种子、样本、区域、场景分组和输出目录。旧实现中的 `CASE/PRIOR`、`prepare()`、`Operator`、历史 P01～P21 分组和固定十五款打包函数不能原样用于新用户。不要覆盖旧案例或生产模型来迁就硬编码，也不要让用户手工复刻研究目录结构。

相机 JSON 的照片／取景原生参数分别编码，**不能将照片 Gamma／系数块直接复制为取景参数**。网格单独拟合时可按已有适配策略同步照片与取景网格，但不代表两条原生处理链完全相同。遵循真实的编解码器及能力声明。

若采用 ROI 图集加速，必须保留空间算子的真实邻域，并在代表区域与全尺寸出图比较后再使用。历史实现的 12 像素 halo、1400×933 坐标及固定图集宽度不是任意新图可照抄的合同。保留本次实际可再次执行的命令，不编造尚不存在的 `train --dataset` 等接口。

## 已知工程坑

- `material_torch.lab` 的输入为 0～255，其他 Lab 函数可能要求 0～1；核对单位，避免多除一次 255。
- 非线性显影不能先把一大块像素平均后再应用模型。保留原像素，或使用与正式渲染等价的节点聚合。
- R5 参考网格可能本来存在很大的相邻跳变；不能一概套“相邻差 ≤4”。保护最终颜色连续性和相对改变量。
- 当前相机网格为 1215 项，渲染器的 `129³` 加速表不是相机的网格大小。
- 历史 32 GiB 内存主机曾在三路 PyTorch 进程下耗尽提交内存；先串行，按主机内存与显存决定并发。该机器最多两路的经验不是所有机器的通用上限。
- Windows 判断训练进程存活使用系统查询接口，不能用 `os.kill(pid, 0)`。
- 没有专业色卡的自然场景测试仍可计算相对目标的色差；不要称为通过标准色卡／绝对色准认证。
- 用户照片、TIFF、权重、Sony 常量和候选 JSON 不自动加入 Git／LFS。公开方法文档不意味着这些依赖已公开分发。
