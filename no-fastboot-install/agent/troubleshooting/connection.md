# USB 连接与恢复

[返回索引](README.md) · [机器检索索引](index.json)

先核对当前任务和构建。以下是已归纳的历史经验，不是对新故障的自动诊断；处理始终服从当前正式入口的待办。

<a id="usb-007"></a>
## USB-007 · USB 字符串描述符：没有 langid

**匹配线索：** `The device has no langid`、`USB 描述符暂时无法读取`、`Entity not found`、`backend -5`。

**阶段：** 普通身份读取。**原因状态：** 同症状有多个可能原因。

**历史原因：** PyUSB 旧路径会吞底层错误并缓存空 LANGID；同一句话可能来自句柄/枚举、权限或待系统重启，不能直接认定管理员权限不足。

**本轮应核对：** 读取 usb_identity 诊断、errno/backend_error、当前 StageBind 的 reboot_required，确认失败发生在首次备份前还是已完成 p1 后的菜单阶段。

**处理：** 现有程序只对描述符做有限重新枚举；等待其结果。需要重启 Windows 时按 USB-002；其他情况按当前恢复待办处理。

**不要这样做：** 不硬填 0x0409、不用 Windows 文字或旧序列号冒充真实身份，不循环重发认证或写入。

**证据与验证范围：** 2026-10-28 GET_DESCRIPTOR 失败有现场证据；11-06 的另一份完整 state 同时证明未处理的重启要求，不能混为所有案例同一根因。

<a id="usb-008"></a>
## USB-008 · 服务模式 0336 无法唯一枚举

**匹配线索：** `Service 0336 did not enumerate uniquely`、`0336`、`service_count`。

**阶段：** 服务身份切换。**原因状态：** 历史案例已确认。

**历史原因：** 一个新电脑案例在认证成功后枚举不到服务设备：旧包只覆盖普通 PID，服务 PID 无驱动。旧开发电脑依赖研究时遗留的驱动，因此漏测。

**本轮应核对：** 核对正常身份认证是否成功、切换后服务枚举数，以及对应服务驱动准备结果。多设备与完全无设备不是同一种问题。

**处理：** 由正式工具准备完整普通/服务驱动组；已有会话先按其结果结束或恢复，再按获允许的后续步骤处理。

**不要这样做：** 不重复认证试探、不手动 Zadig 换未知驱动、不把开发电脑成功当作新电脑已验证。

**证据与验证范围：** 2026-10-31 V2 新旧配置对照确认原因，随后双驱动及缺共同安装器问题分别修复。

<a id="usb-009"></a>
## USB-009 · USBSTOR 已恢复，但 PMHOME／盘符未出现

**匹配线索：** `USBSTOR`、`PMHOME`、`WAITING_FOR_RESTART`、`USB_RESTORE_WAITING`、`请检查所连接的设备`。

**阶段：** 普通 USB 恢复。**原因状态：** 同症状有多个可能原因。

**历史原因：** 驱动切回、设备重新枚举和相机固件操作完成是不同状态。历史多次需要真实重新插拔才能确认普通连接。

**本轮应核对：** 查看 normal_usb_restored、恢复原任务状态、相机是否仍在安装、是否明确要求 Windows 重启；磁盘缺失不能反推 p1 写入失败。

**处理：** 只有当前待办允许时，明确指导保持相机开机重新插拔 USB，并等回复；随后查询同一恢复任务，不重复调度。需要重启 Windows 则改用 USB-002。

**不要这样做：** 不因没有盘符重写 p1；不能把历史用户的“拔插”误记成相机重启证明。

**证据与验证范围：** 多轮用户拔插及恢复回执验证普通连接；具体未来故障仍以当前枚举和待办为准。

<a id="usb-010"></a>
## USB-010 · 既不能写入，也不能恢复

**匹配线索：** `没有可核对的写入材料`、`写入结果尚未证明已结束`、`不能切换驱动`、`DRIVER_BIND_OUTCOME_UNKNOWN`。

**阶段：** 异常恢复分流。**原因状态：** 同症状有多个可能原因。

**历史原因：** 旧版把初始化/描述符等写前失败统一当成未知写入，因不存在 writer 材料而形成循环；真实写入结果未知也会正确触发此限制。

**本轮应核对：** 先核对失败阶段、device_started、firmware_write_attempted/written、reader/writer 的开始和终态、菜单是否启动。文件缺失或 false 单字段不能代替完整证明。

**处理：** 使用原任务正式恢复分流；若已有补丁完整回读而菜单尚未启动，只继续菜单或连接恢复。证据不足时收集具体缺项，不猜成写前失败。

**不要这样做：** 不删除 state/claim/ProgramData、不手动更改 passed/safe_to_restore，不以恢复连接为由重新写入。

**证据与验证范围：** 2026-10-25 本地 JSON 写前失败、10-28 描述符与重启、11-06 初始绑定错误有不同已确认案例；后续分别修复。

<a id="usb-011"></a>
## USB-011 · 另一目录或桌面任务尚未结束

**匹配线索：** `OTHER_INSTALLATION_PENDING`、`另一工具目录仍有未结束任务`、`AI Agent 任务尚未结束`。

**阶段：** 任务协调。**原因状态：** 预期协调保护。

**历史原因：** 共享记录用于防止 Agent、桌面端或不同解压目录同时操作同一机身；新版本目录不能替代原任务结案。

**本轮应核对：** 查 original_tool_directory、原 job 及是否有真实完成/恢复结果；不要通过当前新目录猜测旧任务。

**处理：** 回到原目录，用其正式 status/resume/recover-usb 继续原任务；若原目录缺失，保留共享记录并整理缺失项。

**不要这样做：** 不自动复制状态到新构建，不因版本改为 1.00 就忽略旧任务，不同时启动两个入口。

**证据与验证范围：** 实验 Agent 的共享任务与独立构建身份检查已覆盖；这是预期保护，不应“修复”为直接放行。
