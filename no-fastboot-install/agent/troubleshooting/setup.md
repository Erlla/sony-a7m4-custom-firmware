# 初始化、授权与 StageBind

[返回索引](README.md) · [机器检索索引](index.json)

先核对当前任务和构建。以下是已归纳的历史经验，不是对新故障的自动诊断；处理始终服从当前正式入口的待办。

<a id="usb-001"></a>
## USB-001 · StageBind：证书不受信任

**匹配线索：** `StageBind`、`0x800B0109`、`-2146762487`、`CERT_E_UNTRUSTEDROOT`。

**阶段：** 驱动暂存。**原因状态：** 历史案例已确认。

**历史原因：** 一份新电脑日志证明驱动签名链不被信任，失败在暂存阶段；它与 Defender 的 Bearfoos 告警是两件事。

**本轮应核对：** 读取该 StageBind 原任务结果、stage.log/stage_error.log 中的原始数值与阶段；仅出现 StageBind 标题不能套用此结论。

**处理：** 通过当前正式初始化待办说明 libwdi 公钥证书用途，等待用户在系统授权窗口明确选择；取消后按新 pending 继续。恢复只走程序允许的原任务入口。

**不要这样做：** 不手工导入未知证书，不关闭签名检查，不删除任务后重试；mutation 标记为真不等于已经成功绑定或写入。

**证据与验证范围：** 2026-10-31 实际归档确认原因，证书授权与分流经过隔离测试；不能据此保证所有 Windows 策略都接受此驱动。

<a id="usb-002"></a>
## USB-002 · StageBind／Restore：需要重启 Windows

**匹配线索：** `reboot_required`、`3010`、`WINDOWS_RESTART_REQUIRED`、`USB_RESTORE_WINDOWS_RESTART`。

**阶段：** 驱动绑定或恢复。**原因状态：** 历史案例已确认。

**历史原因：** 历史 StageBind 已返回 reboot_required=true，旧主机仍继续读取描述符；另一恢复任务返回 3010 后被误分类成失败。

**本轮应核对：** 核对当前原任务 reboot_required、uninstall_exit_code、程序给出的重启待办及重启后确认；不要只看 USBSTOR 字样。

**处理：** 明确请用户保存电脑工作、在 Windows 选择“重新启动”；等待真实回复，再在原目录查同一任务并按 pending 继续。

**不要这样做：** 重开软件、重启相机和拔插 USB 不能替代 Windows 重启；不要由 Agent 自动重启电脑或重复调度驱动任务。

**证据与验证范围：** 2026-10-28 与 11-06 实际记录确认；后续修复区分重启、重枚举与未知写入。

<a id="usb-003"></a>
## USB-003 · StageBind：驱动文件缺失

**匹配线索：** `stage_svc.log`、`WdfCoInstaller01011.dll`、`WinUSBCoInstaller2.dll`、`系统找不到指定的文件`。

**阶段：** 驱动暂存。**原因状态：** 历史案例已确认。

**历史原因：** 旧服务驱动包仅带 INF/CAT，缺失 INF 依赖的 amd64 共同安装器；后续又发现部署器没有创建其父目录。返回码 2 本身并非唯一诊断。

**本轮应核对：** 按报错记录核对暂存对象、缺失文件名和是否在部署复制阶段停止；读取日志，不要求 Agent 对整个展开目录重算哈希。

**处理：** 使用资源清单固定的完整修复包；无活动任务时可向新短目录重新解压同一已校验 ZIP。已有任务先查原记录，由正式初始化处理残留。

**不要这样做：** 不从论坛拼装 DLL、不改 INF/CAT、不把目录存在视为初始化完成。

**证据与验证范围：** 2026-10-31 受控 pnputil 布局对照证实缺文件，后续日志修正了“已成功安装”的早期误判。

<a id="usb-004"></a>
## USB-004 · 首次初始化：目录或任务已存在

**匹配线索：** `A task folder already exists`、`An installation already exists`、`refusing replacement`。

**阶段：** 首次初始化。**原因状态：** 历史案例已确认。

**历史原因：** 旧初始化不可重复执行：上次中断留下目录，或任务目录已存在但并未完整登记。目录存在不证明相机操作发生。

**本轮应核对：** 查询初始化收据、device_started、任务是否运行与 failed_fields；区分可复用匹配配置、空/部分配置和未知活动任务。

**处理：** 当前正式初始化核对匹配配置、补建缺失任务；按 pending 重试初始化，不重新 start 已经派发的相机任务。

**不要这样做：** 不要沿用早期“删除 ProgramData、任务目录、enrollment”的建议。它已被后续保留记录的初始化修复替代。

**证据与验证范围：** V4/V5 截图与归档确认，2026-11-01 完整隔离初始化覆盖中断和已有任务；模拟不等于全新 Windows 实机。

<a id="usb-005"></a>
## USB-005 · 任务定义误判：账户名与 SID

**匹配线索：** `Unexpected task definition`、`task_checks`、`principal_resolved`、`failed_fields`。

**阶段：** 首次初始化。**原因状态：** 历史案例已确认。

**历史原因：** V6 将 Windows 返回的账户名与注册时 SID 直接作字符串比较；真实任务服务会将同一用户以账户名读回。也可能存在其他真实定义差异。

**本轮应核对：** 查看 task_checks 的 failed_fields，区分仅 principal 表示差异与动作、路径、用户、触发器不匹配。

**处理：** 使用已含 SID 规范化的构建，按正式初始化继续；仍有字段不符时保留具体字段供维护者核对。

**不要这样做：** 不能只因任务名字相同就删除重建，不能放宽其他用户或未知任务动作检查。

**证据与验证范围：** 2026-11-01 在真实 Windows 任务服务只读复现并验证规范化；没有变更参考任务。

<a id="usb-006"></a>
## USB-006 · UAC 取消或授权窗口尚未确认

**匹配线索：** `ADMIN_CANCELLED`、`1223`、`AWAITING_SYSTEM_AUTHORIZATION`、`首次使用`。

**阶段：** 后台授权。**原因状态：** 同症状有多个可能原因。

**历史原因：** 取消、系统窗口未处理和受保护后台启动失败需分开。等待授权本身不是写入失败，命令超时也不证明后台已停止。

**本轮应核对：** 查同一 job 的 pending、launch-error、dispatch 与原始 winerror。只在明确 ADMIN_CANCELLED 后按新的请求编号继续。

**处理：** 告诉用户需要确认哪个 Windows 窗口及原因；等真实回复，用程序当前命令继续。仍等待时只查询原任务。

**不要这样做：** 不代点 UAC、不自动同意证书、不反复 start，也不把旧“同意”映射到新的 pending.id。

**证据与验证范围：** Agent 状态机覆盖取消与独立后台；历史演练中确有重新请求授权。
