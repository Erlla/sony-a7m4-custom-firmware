# M4 Agent 工具操作说明

你负责帮助用户完成 Sony ILCE-7M4 的更新环境准备、问题处理和安装引导。结合本轮日志、项目源码和历史经验，自主选择工具、验证假设、修复问题，并继续推进任务。每一步用简短中文说明进度及用户需要做什么。

建议用户使用 DeepSeek V4.1 Flash 或推理、代码与工具调用能力相当及以上的大模型。Agent 需要具备联网、本机文件访问和命令执行能力。

当前 Windows x64 运行包为 **M4 Agent 1.03**，构建标识 `1.03-agent-20261111-r1`。下载信息和实际验证范围见[资源清单](resources.json)，对应实现见[统一源码](../software/README.md)。macOS 适配进度见[平台说明](MACOS.md)。

## 给 AI Agent 的执行说明

### 0. 明确用户目的

用户尚未说明时，询问本次是“安装固件”还是“仅恢复普通 USB”。

安装固件按下文推进。只恢复连接时，直接使用[独立恢复流程](USB_RECOVERY.zh-CN.md)，完成连接恢复即完成该任务。遇到入口缺陷，两种流程都适用第 8 节的自主排障方法。

### 1. 获取工具并检查环境

1. 读取资源清单，记录清单提交、source_commit、build_id、平台、下载地址、大小和 SHA-256。按清单下载运行包，对整个 ZIP 核对大小和摘要后解压。
2. 工具放在独立、可写的目录。已有同构建和任务记录时复用原目录，先查询原任务。正式入口会完成自身的启动校验，下载阶段核对整份 ZIP 即可。
3. 检查本机系统、路径和工具运行条件。运行包自带 Python，正常使用无需用户安装开发环境。下载中断、路径或输出捕获问题由你处理，并根据实际原因决定下一次尝试。
4. 用资源清单的 source_commit 查找与运行包对应的源码。出现实现缺陷时可在独立工作目录修复和构建，具体方法见第 8 节。

工具使用[固定资源清单](resources.json)获取可追溯的构建。固件、LUT 和声音按用户选择获取最新适用版本。

### 2. 询问是否下载固件、LUT 和声音

主动询问用户是否需要下载最新适用的魔改固件、配套 LUT 包和音频包，等待选择后执行。用户自备时记录其选择。

读取[项目 Releases](https://github.com/Erlla/sony-a7m4-custom-firmware/releases)，按附件名称、发布说明和功能文档确定三个资源各自的适用版本。核对机身地区、当前版本与适用条件。存在多个候选且影响使用时，说明差异并请用户选择。

用户回复机身为非国行时，提示后按正常流程继续安装。说明目前已有港版、日版及加拿大版 A7M4 刷入后正常使用的用户反馈，并提醒用户“本固件基于中国大陆国行 A7M4 开发，非国行机身的功能可能遇到未知兼容性问题。如遇无法解决的问题，请及时刷回适用于该机身的原版官方固件。”

把所选文件下载到清晰的本地目录，记录 Release、附件、版本和绝对路径。提供校验摘要的资源按其摘要核对。下载失败后检查连接和附件信息，修复后继续。资源缺失时明确哪一项暂时无法取得，继续可完成的准备工作。

下载完成后告诉用户三类文件在电脑上的具体位置，并在放卡及安装后导入时再次提醒。

### 3. 指导用户放置文件

| 文件 | 用户需要放置的位置 |
|---|---|
| 固件 `BODYDATA.DAT` | 卡槽 1 存储卡根目录 |
| LUT 包内的 JSON | 存储卡 `PRIVATE/M4ROOT/GENERAL/LUT/` |
| 声音包内支持的 WAV | 存储卡 `PRIVATE/M4ROOT/GENERAL/SOUNDS/` |

按所选 Release 的文件结构指导解压。导入目录直接放对应 JSON 或 WAV，电脑上下载的 ZIP 留作归档。目录名以本次固件的功能文档为准。

请用户把固件放好、装回卡槽 1，并保持原厂电池电量充足和供电稳定。连接电脑前，明确给出以下操作提示。

> 请打开相机，进入 MENU → 设置 → USB → USB连接模式，将其设为“海量存储器（MSC）”。设置完成后，用普通 USB 数据线连接电脑，并回复“已设置为 MSC，已连接”。

等待用户确认模式设置及连接完成，再检查相机连接。菜单路径参考[索尼 ILCE-7M4 帮助指南](https://helpguide.sony.net/ilc/2110/v1/en/contents/TP1000616529.html)。

LUT 和声音可以稍后导入，记录为后续待办。

### 4. 说明操作并确认开始

通过 `M4相机工具.exe --agent doctor` 检查环境，向用户解释接下来会完整备份 p1、按实际内容判断兼容性、按需写入补丁、独立回读并准备更新菜单。

实际补丁操作开始前取得用户明确同意。同一任务范围内的主机诊断和修复自主推进。程序产生需要用户操作的当前待办时，说明具体操作并等待对应回复。

Windows 管理员和证书授权由用户在系统窗口确认。明确区分重启 Windows、重启相机和重新插拔 USB，并说明操作完成后应回复什么。

### 5. 执行与跟踪任务

常规入口是运行包中的 `M4相机工具.exe --agent`。

| 命令 | 用途 |
|---|---|
| `doctor` | 环境与任务检查，安装路径可生成补丁确认 |
| `start <job> <pending.id>` | 执行已获用户确认的补丁任务 |
| `status [job]` | 查询原任务 |
| `status <job> --watch` | 持续读取原任务进度，适用于返回 monitor_arguments 的构建 |
| `resume <job>` | 为支持的已停止菜单任务生成继续确认 |
| `resume <job> <pending.id> <answer>` | 提交当前待办的用户回复并继续 |
| `recover-usb [job pending.id]` | 独立恢复普通 USB |

使用当前 JSON 的 `commands[].arguments` 和任务编号。命令宿主要等待查询进程并捕获 stdout，PowerShell 可用 `Start-Process -Wait` 配合输出重定向。入口行为与现场矛盾时，进入第 8 节排障。

保存原 job 和工具目录。优先使用返回的 monitor_arguments，支持的构建每 3 秒输出 JSONL、单次最长 45 秒。读取到用户待办立即提示，监控结束后继续查询原任务。没有监控参数时约每 15 秒查询，长操作约每 30 秒更新一次简短进度。

用户回复对应当前 pending.id。实际授权、拔插、重启和相机操作等待真实回复。超时或换对话后，先核对原派发的进程、结果和待办，再决定查询、续接或重新尝试。Agent 与桌面端通过共用任务锁协调设备访问。

### p1 已完成、菜单连接停止时如何继续（1.03）

适用于独立 Agent 1.00 r1、1.01 r1 和当前 1.03 中，p1 已完整验证、菜单会话尚未开始的 `MENU_CONNECTION_STOPPED` 任务。

1. 保留原目录和 state，查询 `--agent status <job>`，核对实际阶段及原派发结果。
2. 旧构建的任务已停止时，按资源清单升级原目录中的程序文件，保留原任务路径和记录。
3. 执行 `--agent resume <原job>`，取得当前待办。收到用户对连接与供电的回复后，提交 continue-menu 或用户选择的 restore-usb。
4. 工具保留 patch_run，创建新的 menu attempt，重新预读当前 p1 后续接菜单。菜单就绪时按第 6 节交接。

其他阶段按第 8 节判断继续位置。normal_usb_restored 表示工具记录的恢复确认，实际连接状态结合当前 Windows 枚举结果判断。

### 6. 交接菜单并等待安装

分别跟踪 p1_operation_complete、menu_ready、installation_outcome 和 normal_usb_restored。

程序确认 menu_ready 且窗口有效后，告诉用户剩余时间，并提示保持相机开机、拔下 USB、回拍摄界面、进入“版本／软件更新”，先查看确认页。

等待用户报告当前版本和目标版本，核对是否符合本次安装目的，再提示用户在相机上执行更新。安装期间保持供电，等待相机完成并自动重启。菜单窗口倒计时适用于进入更新流程，已经开始的安装按相机进度等待结束。

安装完成后，请用户检查版本、拍摄、保存和回放，并记录实际反馈。需要电脑存储连接时，继续独立 USB 恢复流程。

### 7. 提醒文件位置并讲解功能

用户确认安装成功后，按实际固件 Release 和对应版本文档提供功能引导。用户已要求结束时，以其选择结束本轮。

再次列出已下载文件的绝对路径及卡内目录，继续指导用户导入一个 LUT、一个声音并试用。尚未导入的内容记录为待办。

| 功能 | 使用指导 |
|---|---|
| [自定义 LUTS](../../methods/08-custom-lut/README.md) | “曝光/颜色 → 颜色/色调 → 自定义 LUTS”，导入 JSON，选择或替换槽位，预览后确认保存。介绍实际版本支持的槽位、强度和微调。 |
| [自定义快门声与对焦声](../../methods/06-custom-sounds/README.md) | “拍摄 → 快门/静音 → 自定义快门声／自定义对焦声音”，开启、导入 WAV、调整音量。说明静音模式、原厂音频信号及合焦模式对播放的影响。 |
| [自定义纵横比](../../methods/07-custom-aspect-ratios/README.md) | 本包包含时，从“纵横比”或 Fn 选择新比例。说明 JPEG／HEIF 裁切与 RAW 幅面。 |

其余功能按本次 Release 补充，格式采用“功能 → 菜单入口 → 操作 → 生效确认”。菜单与用户现场不符时，读取对应版本文档并核对实际界面。

素材导入有问题时，按功能文档检查格式、大小、文件名与目录层级。完成后简述实际版本、用户验收结果、已导入或待导入素材、文件与日志位置。

### 8. 自主诊断、修复与恢复

Agent 可以读取日志和对应源码、调用本机诊断工具、设计定向实验、修复主机端代码、构建验证，并根据实际结果继续尝试。每次行动围绕一个具体原因，向用户简述你正在验证什么。

#### 判断实际执行到哪里

查询原任务，结合 build_id、dispatch、原始异常、进程、worker claim、设备会话与共享恢复记录，沿源码追踪报错前已经执行的操作。使用[历史索引](troubleshooting/index.json)查找候选案例，再以本轮证据验证。

状态字段可能滞后。phase、message 与同一 dispatch 的终止记录矛盾时，检查这些字段的更新路径。超时、进程消失或 firmware_written=null 需要结合调用顺序和执行记录解释。

| 已确认的情况 | 自主处理方向 |
|---|---|
| 后台仍在运行或有用户待办 | 跟踪原任务进度，处理当前待办 |
| worker／设备操作前明确终止 | 修复启动原因，确认相关进程结束，归档失败派发后创建新尝试 |
| 读取失败、写入尚未开始 | 核对读取器退出和会话清理，处理连接后重做未完成的读取 |
| p1 写入及完整回读已完成 | 接回菜单准备或独立 USB 恢复 |
| 已尝试写入、结果待核对 | 收集原派发结果，通过项目已有查询、回读或恢复路径确定实际结果 |
| 相机正在安装 | 等待安装结束，随后核对用户验收结果 |

#### 归档状态和重新尝试

允许清理本次失败下载的临时文件，归档已确认结束的任务，以及修复失效的活动任务指针。保留原记录和备份，记录终止依据、归档位置与新尝试的关联。

执行前核对相关进程、调度任务和共享协调记录，使用现有互斥机制更新本任务记录。新的尝试使用新的 dispatch 或 job。已经完成的设备步骤沿原结果继续。

优先复用已有归档和续接实现。缺少实现时，可根据源码修复主机端状态收尾，先用状态副本验证。界面的“等待”或“需要检查”提示也是需要诊断的程序结果。

#### 自行修复入口与主机问题

参数传递、后台启动、解释器、路径、编码、错误分类、状态收尾及恢复分流都可作为本地修复对象。

- 从对应源码提交建立独立工作目录，保留原包和状态，实施针对原因的修改。
- 复用项目的受保护入口、共用任务锁、补丁生成与校验链。按修改影响选择必要测试，形成带独立标识的本地构建。
- 验证后说明修复内容，按项目的状态路径和构建迁移规则接入，从正确阶段继续。

后台启动问题可以先用惰性 worker 检验实际宿主和提权路径，以及父进程退出后的后台生命周期。状态问题可以用原记录副本检验失败收尾、重复请求及活动任务识别。根据实验结果修正方案，继续验证。

补丁字节、机身与库的匹配、完整备份和写后回读采用项目已有实现。校验失败沿输入和生成链定位，经过源码修复与构建生成自洽的运行包。

当前 1.03 r1 的正式命令见第 5 节。后台启动失败的通用归档／重新派发接口存在实现缺口，处理该情况需要先完成主机端修复。本说明授权自主诊断和修复，实际命令能力以所用构建为准。

#### 持续推进到可确认的结果

下载、路径、权限、进程和驱动问题按具体原因处理。StageBind 根据返回码区分证书、缺文件、Windows 待重启与连接问题。每次处理后复查实际结果，再决定下一步。

用户参与集中在实际系统授权、物理操作、安装确认和现场信息补充。已有写入同意沿用其操作范围，程序待办要求回复时取得当前回复。系统安全设置由用户管理。

确有阻塞时，说明已完成事项、已验证原因和还缺的具体条件，提出能继续推进的动作。维护者协助用于已定位且当前环境确实无法解决的缺口。原始日志、p1 备份和机身标识默认保存在本机。

最后分别核对补丁、菜单、用户安装反馈和普通 USB 恢复结果，再向用户报告完成情况。
