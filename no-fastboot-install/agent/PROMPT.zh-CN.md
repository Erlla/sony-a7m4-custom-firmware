# M4 Agent 工具：交给本地 AI Agent 的操作说明

## p1 已完成、菜单连接停止时如何继续（1.01）

适用于 Issue #24 的独立 Agent `1.00-agent-20261110-r1` 原任务：p1 已完整验证、菜单窗口未启动，原任务停在 `MENU_CONNECTION_STOPPED`。Windows 存储卡可读与 `normal_usb_restored=false` 可以同时出现，后者只是工具尚未记录恢复确认，不能仅凭它判定驱动坏了。

1. 保留原工具目录和全部 `state`。先用原入口 `--agent status <job>` 查询；若仍为 RUNNING/DISPATCHING 或写入结果未知，不覆盖程序，不重复派发。
2. 确认是上述停止情况、没有活动设备任务后，关闭工具前端。将资源清单中的 1.01 修复包解压，把 `M4Agent_1.01` **目录内的文件和子目录**覆盖到同一个原工具目录（即使原目录名仍叫 `M4Agent_1.00`），保留 `state`；不要把整个新目录嵌套进去；不要换目录、复制旧状态到另一安装或删除旧记录。先保存原程序副本以便仍需使用原构建查询其他任务。
3. 在升级后的原目录执行 `--agent status <原job>`，再执行 `--agent resume <原job>`（此步不带待办编号）。后者只生成新的用户确认，不读写相机。
4. 明确询问用户相机没有在安装、USB 已连接且供电稳定，取得回复后，使用 JSON 返回的 `recover-usb` 参数确认连接。恢复成功后应出现 `MENU_CONTINUATION_READY` 和 `continue-menu` 待办；此时仍不能拔线安装。
5. 询问用户是否继续菜单准备，再提交当前 `resume` 参数。工具验证原 p1 证据，保留旧菜单计划，生成新菜单 attempt，重新读取当前 p1 并准备 RAM 窗口，不重新派发 p1 writer。只有正式 JSON 明确返回 `menu_ready=true` 并给出查看相机菜单的当前待办，才提示拔线。

旧构建、旧待办编号和新构建不能随意混用。1.01 仅接纳上述已停止的独立 Agent r1 菜单任务；旧写入未确认、预读已开始、RAM 窗口已运行、claim 已消费或证据不符均停止。桌面 1.02 的任务不是 Agent job，不套用这组命令。

如果相机未在更新、可正常拍摄，且日志确认 p1 会话结束、菜单 `stopped_before_session=true/window_started=false/preread_started=false/installation_may_be_running=false`，可正常关机；关机后再继续必须重新核对连接和当前 p1。缺少这些证据时先核对记录，不用删状态或尝试官方 DAT 排障。“恢复普通 USB”不回滚 p1。

**模型建议：使用 [DeepSeek V4.1 Flash](https://api-docs.deepseek.com/news/news260910/)，或推理、代码与工具调用能力不低于该级别的大模型；Agent 还须具备联网、本机文件访问和命令执行能力。**

开始前向用户说明这项模型建议与本机操作能力要求，再按下文区分安装固件和仅恢复 USB。

将本页链接交给能够联网、访问本机文件并执行命令的 AI Agent。Agent 应按下面的说明逐步操作，并持续告诉用户现在需要做什么。

**独立 M4 Agent 工具 1.01 已作为 [GitHub 正式版附件](https://github.com/Erlla/sony-a7m4-custom-firmware/releases/tag/A7M4-Agent-ToolKit-V1.01) 提供，构建标识 `1.01-agent-20261111-r1`；桌面端版本不变。** 附件大小、SHA-256 和离线验证范围见资源清单；本构建的全新 Windows 与真实相机整轮验收尚未完成。正式使用以[资源清单](resources.json)固定的附件为准，先按本页检查，再在补丁开始前取得明确同意。Agent 自动获取工具包；魔改固件、LUT 和声音是否下载，先询问用户。SD 卡文件放置和相机最终安装仍由用户完成，安装后按实际版本讲解功能。排障见[历史问题与版本说明](troubleshooting/README.md)。

## 给 AI Agent 的执行说明

请使用 [Erlla/sony-a7m4-custom-firmware](https://github.com/Erlla/sony-a7m4-custom-firmware) 的 M4 Agent 入口，帮助用户操作自己的 Sony ILCE-7M4。

### 0. 区分安装与单独恢复

用户只要求恢复 USB 驱动／普通连接时，使用[单独恢复 USB 指南](USB_RECOVERY.zh-CN.md)。按第 1 节获取并校验工具包，随后先查原任务、直接进入正式 `--agent recover-usb` 流程；跳过下面的固件／素材下载、放卡、补丁确认、菜单准备与安装步骤。不要先调用会创建补丁确认待办的 `doctor`。恢复中的用户提示、真实回复和第 8 节排障规则仍适用；不把原任务的写入或继续菜单待办当作恢复操作提交。

用户要求安装固件时，先按第 2 节明确本次固件和素材的下载选择，再进入放卡与补丁流程；用户尚未明确选择时必须主动询问，不能省略。

### 1. 检查能力与获取 Agent 工具

- 你必须能操作相机连接的本机文件和终端。纯网页聊天、云端沙箱或没有本机 USB 访问能力的环境不能完成操作。
- 先读[历史问题索引](troubleshooting/README.md)的版本说明，只需一次。旧实验 `1.02-agent-20261110-r1` 有已知启动缺陷，不用于新写入；它与当前独立 `1.01-agent-20261111-r1` 是不同构建。已有任务仍在原目录按正式入口查询和恢复，不混用记录。不要为绕过已知问题临时改源码或换成桌面包。
- 当前只支持 Windows x64；macOS 尚未完成实机适配，说明限制后停止相机操作。
- 先读取本目录的 [资源清单](resources.json)，记录这份清单所在的 GitHub 提交，再按该提交保存清单。核对 `published=true`、Windows x64 平台、构建标识、确切附件 URL、大小和 SHA-256。若 `release_channel` 或 Windows `status` 为 `prerelease`，必须说明测试范围与尚未验收的项目，不能称为正式稳定版。`source_commit` 指向已公开的源码快照，`source_path` 为源码目录；`build_source_commit` 保留运行包的原始构建来源记录。这些字段用于追溯，不要求用户检出源码，也不现场编译。
- 仅从清单的确切 URL 下载，Windows 状态只接受明确标记的 `prerelease` 测试包或 `validated` 已验收包；未发布、字段缺失或其他状态先停止。将 ZIP 保存到独立的构建目录，按大小和 SHA-256 核对后解压。已有相同构建和运行记录时先查询原任务，不覆盖目录。不使用 `latest`、旧桌面包、未知镜像或自己猜的下载地址。
- 下载总计最多尝试三次；大小或摘要不符时停止使用该文件，按第 8 节排查，不能运行未核验包。下载完整运行包，不拉源码现场编译上位机，不自行编写补丁，不要求用户预装 Python、Git 或编译器。既有工具内部仍用随包锁定组件生成单次任务，不改写这条生成链。
- 下载阶段只核对整个工具 ZIP 的大小和 SHA-256；通过后正常解压。Agent 不再逐文件计算解压目录的哈希，不遍历发布清单重复检查，也不额外执行 `--verify`。正式入口自身的启动校验由程序处理。已有同一构建且原任务存在时直接查询原任务，不重复下载、解压或覆盖。

### 2. 询问是否下载最新魔改固件、LUT 包和音频包

**安装流程中，若用户尚未明确下载选择，必须主动询问并等待真实回复：**

> 是否需要我帮你下载最新适用于这台相机的魔改固件，以及配套的 LUT 包和音频包？

提供以下选择，并允许用户只选其中一项：

- 下载最新适用的魔改固件、LUT 包和音频包。
- 我已有固件，只下载最新兼容的 LUT 包和音频包。
- 我已自行准备，跳过下载。

用户已明确作出选择时沿用本轮选择，不重复询问。不能把“开始安装”“同意打补丁”当作下载三类文件的选择，也不能默认全部下载或全部跳过。仅恢复普通 USB 时不询问此项，按第 0 节执行。

用户也可以只指定其中一项。按实际选择下载，不因用户同意准备 USB 补丁就推定同意下载或替换固件。此选择不影响第 1 节获取正式 Agent 工具包。

若用户自行准备，确认文件实际位置及来源；提醒 BODYDATA.DAT 放入卡槽 1 根目录，素材路径按第 3 节说明。不强制重新下载或替换现有文件，不把本地文件擅自归为“最新版”或“已验证兼容”。用户不需要素材时记录为跳过，照常继续已获授权的补丁流程。

需要协助下载时，由你获取用户选择的类别，不再要求用户自行寻找链接。先阅读[安装指南](../README.md)、所选 Release 的说明和下面的功能文档，询问相机型号、地区版本与当前固件，核对适用条件。下载不代表已确认该机可以安装。

1. 查询本仓库的 [Releases API](https://api.github.com/repos/Erlla/sony-a7m4-custom-firmware/releases?per_page=100)，按需继续分页。**用户选择下载的类别分别按 `published_at` 选择最新、适用于本次固件的正式附件**，排除草稿和预发布；不要把排在最前的 Agent 工具 Release（即使是正式版）当作最新相机固件。若素材包有固件版本要求，按说明选择最新兼容版本并解释原因。
2. 根据 Release 说明识别这三类附件：

   | 类型 | 要获取的文件 | 要区分的内容 |
   |---|---|---|
   | 相机固件 | `BODYDATA.DAT`，或 Release 明确指定、内含该文件的固件包 | Agent／桌面工具 ZIP、Source code、Fastboot 包都不是相机固件 |
   | LUT 滤镜 | 面向相机导入的 LUT ZIP，例如 `Lut-v*.zip`、`Luts*.zip` | `M4-LUT-training-assets.zip` 是电脑训练素材，不能代替滤镜包 |
   | 音频 | `SOUNDS.zip`，或 Release 明确指定的 WAV 素材包 | 下载音频素材，不下载声音功能的源码构建产物 |

   附件命名变化、同类有多个候选或缺少一类时，先核对发布说明；不能猜链接、静默混用不兼容包或把缺失说成已完成。
3. 选定后记录所需类别的 Release 标签、附件 ID、确切下载 URL、大小和预期 SHA-256，并固定本轮选择。**“最新”在每次新安装开始时重新查询；已有任务中不自动更换固件或素材。** Agent 工具本身仍只使用第 1 节资源清单固定的构建，不用这些内容附件替换工具。
4. 下载用户选择的附件到本机可写、路径较短的独立目录；不同附件可独立并行下载，不并行操作相机。复用本轮已通过摘要核验且未改变的下载，不重复下载相同附件。向用户报告各项进度；每个附件下载失败总计最多三次。按 GitHub 附件 `digest` 或该 Release 的校验清单核对 SHA-256 和大小；列表缺少摘要时先查询该附件 API 和发布校验文件；仍缺少预期摘要时不能宣称已校验通过，再说明需要维护者补充。摘要不符停止使用该文件，不改用未知镜像。
5. 固件若直接为 `BODYDATA.DAT`，无需解压；若为固件 ZIP，按发布说明解压取得它。LUT、音频 ZIP 解压到各自目录，检查解压路径，保留原始附件。只做下载完整性和文件整理，不修改 DAT、重签固件或运行包内未知程序。向用户提供已取得文件及解压结果的**实际绝对路径**，不要只报“下载完成”。

### 3. 在适当阶段提示用户放置文件

**在启动补丁前**，给用户下面的放置表，仅列用户要使用的文件，并把“电脑中的文件”替换成实际下载／解压或用户提供的位置。由用户用读卡器或正常存储连接复制；你不自动复制到相机或 SD 卡、不格式化卡、不覆盖卡内已有文件。若已有相机任务未结束，先按原任务待办处理，不让用户在写入或服务会话中拔卡／拷卡。

| 电脑中的文件 | 卡槽 1 存储卡上的位置 |
|---|---|
| 本次选定的 `BODYDATA.DAT` | 卡根目录：`BODYDATA.DAT` |
| LUT ZIP 解压出的所需 `.json` | `PRIVATE/M4ROOT/GENERAL/LUT/`，JSON 直接放在这一层 |
| 音频 ZIP 解压出的所需 `.wav`／`.WAV` | `PRIVATE/M4ROOT/GENERAL/SOUNDS/`，WAV 直接放在这一层 |

不要把 ZIP 直接放进导入目录，也不要多套 `Lut-v…/` 或 `SOUNDS/` 文件夹。固件版本更新不会自动导入滤镜或音频；可以先一次放好三类文件，素材的机内导入在安装成功后再做。

先让用户确认固件已放入卡槽 1 根目录、存储卡已装回相机，再进入补丁确认。LUT 和音频是否已放好也单独记录；若用户暂时不放，保留为安装后的待办，不把它混同成固件更新失败。

### 4. 先解释并取得用户确认

- 每个阶段先用简短中文说明正在做什么、是否需要用户操作。等待较长时持续更新阶段和进度。
- 通过正式 `M4相机工具.exe --agent doctor` 检查环境，转述返回的 `message` 与 `pending.message`。
- 补丁开始前说明会完整备份 p1、按实际内容判断兼容性、按需写入并独立回读，然后准备更新菜单。
- 明确询问用户是否已放好安装包、只连接这一台 M4、电量充足且能保持供电，以及是否同意开始补丁操作。必须收到真实、明确的同意，才能执行当前 `start` 命令。
- 同一任务、同一构建和同一操作范围已获明确同意后，不重复询问是否允许写入；遇到程序新待办、任务或构建发生变化时按当前要求确认。Windows 管理员和驱动证书授权由用户在系统窗口确认。解释授权用途，取消后按程序返回的原因和待办继续；不代点、不修改系统安全策略或自动关闭安全软件。

### 5. 只使用正式入口，按原任务继续

支持的命令为：

| 命令 | 用途 |
|---|---|
| `--agent doctor` | 环境与任务检查 |
| `--agent start <job> <pending.id>` | 用户确认后启动 |
| `--agent status [job]` | 查询原任务 |
| 程序返回的 `monitor_arguments`（如 `--agent status <job> --watch`） | 在支持的构建中持续读取原任务进度 |
| `--agent resume <job> <pending.id> <answer>` | 按当前待办继续 |
| `--agent recover-usb [job pending.id]` | 展示恢复确认或执行获确认的恢复 |

编号必须来自当前 JSON，不照抄表里的占位符。使用程序返回的 `commands[].arguments`，不要自行拼接内部脚本或调用内部 worker。命令宿主要显式等待并捕获 stdout；PowerShell 可用 `Start-Process -Wait` 配合输出重定向。

- 保存 `job`。返回 `monitor_arguments` 时优先使用该数组。支持该功能的构建中，`--watch` 一次核验启动后每 3 秒输出 JSONL，最长 45 秒；出现用户待办或任务结束便返回。宿主应持续读取输出或采用短时让出，不能等整段结束才看提示。监控结束或中断后仍查询同一任务。
- 较旧构建没有 `monitor_arguments` 时，使用原 `status` 每约 15 秒查询，不猜测新参数。没有新待办时约每 30 秒简述阶段与进度；有待办立即提示，不让用户反复打开日志。
- 纯菜单观察回复由支持它的程序直接更新待办。只执行当前返回的 `commands[].arguments`，不为记录“已看到确认页”自行重启管理员后台或调用 `start`。需要系统授权时仍由用户手动确认。
- 收到 `pending` 后，先告诉用户具体要做什么、完成后回复什么，然后等待。用户回复只映射到当前 `pending.id` 的 `answers`。不能用超时、默认选项或上一次回复代替。
- 明确区分真正重启 Windows、正常重启相机、重新插拔 USB，三者不能混用。
- 关闭对话或命令等待超时后，在原目录先查询 `status`；不自动重复 `start`，不结束后台进程，不删除状态来解锁。换对话也继续原任务。
- Agent 和桌面端不能同时操作相机；若提示另一目录存在未结束任务，回到该目录查询。

### 6. 交接菜单，等待用户安装与验收

- 分别检查 `p1_operation_complete`、`menu_ready`、`installation_outcome` 和 `normal_usb_restored`。`query_ok=true` 或退出码 0 只表示命令／查询成功，不等于固件安装成功。
- 只有程序明确给出 `menu_ready=true` 且窗口仍有效，才能提示拔下 USB。告诉用户剩余时间，先回拍摄界面，再进入“版本／软件更新”，停在确认页。
- 等用户报告当前版本、目标版本和确认页状态，并核对是否符合用户预期。未确认前不提示最终执行。
- 按当前待办继续后，提示用户自行在相机选择安装。保持 USB 断开及供电稳定，等待完成。已经开始安装后，不因菜单倒计时结束提示断电。
- 安装结束后请用户检查版本、拍摄、保存和回放，并等待实际反馈。成功只能记为用户验收，不能声称工具回读验证了全部安装后固件。
- 普通 USB 恢复是独立事项，按程序当前待办处理；不为恢复电脑连接重新写入补丁。

### 7. 安装成功后，继续指导导入素材并讲解新功能

**用户未要求结束时，安装完成后主动提供简短功能引导；用户明确结束或跳过素材时尊重其选择。** 等用户确认版本、拍摄、保存和回放正常，并按当前待办记录安装结果后，主动完成以下引导。所述功能以这次安装的固件 Release 和对应版本文档为准；优先使用 Release 引用的版本／提交，不把仓库后续开发内容当作本包已包含。只讲用户操作，不让新手执行文档里的编译或刷分区命令。

1. 重新提醒已下载或用户自备文件各放在哪里，列出实际绝对路径。若素材尚未放好，先按程序处理普通 USB 恢复，再指导用户通过正常存储连接或读卡器放置；需要拔插或操作相机时等回复。没有明确任务结束前，不以导入素材为由切换驱动或重启。
2. 按本包实际支持的功能，给出简短的“**功能 → 菜单入口 → 操作步骤 → 如何确认生效**”说明。至少讲清 LUT 和声音，再覆盖 Release 列明的其他新功能：

   | 功能 | 安装后要告诉用户的用法 |
   |---|---|
   | [自定义 LUTS](../../methods/08-custom-lut/README.md) | “曝光/颜色 → 颜色/色调 → 自定义 LUTS”，导入 → 选择存储卡和 JSON → 选择／替换槽位；预览、右键详细调节、确认保存。说明 16 个槽位、八项微调与强度，首次使用约 1 秒载入，导入后日常使用不依赖卡内原文件。 |
   | [自定义快门声与对焦声](../../methods/06-custom-sounds/README.md) | “拍摄 → 快门/静音 → 自定义快门声／自定义对焦声音”，分别开启 → 从 SD 卡内导入 WAV → 调整音量。说明静音模式会抑制播放、开机后需等数秒；对焦声还受原厂音频信号设置和合焦模式影响。 |
   | [自定义纵横比](../../methods/07-custom-aspect-ratios/README.md) | 若本包包含，从原有“纵横比”或 Fn 项选择新比例；说明 JPEG／HEIF 按比例裁切，RAW 保留原始幅面。 |
   | [FL2／FL3](../../methods/03-fl2-fl3/README.md) | 若本包包含，指导在“创意外观”选择 FL2／FL3并试拍；不要把研发文档里的 CP／NOR 移植步骤当作安装后的日常操作。 |
   | [白平衡优化](../../methods/10-awb-priority/README.md) | 若本包包含，使用原有自动白平衡及标准／氛围优先／白色优先设置，不需要新增菜单或再次打补丁。 |

   其他功能按 Release 说明补充；未经核对的菜单或效果不要编造。菜单找不到时先询问用户实际界面。
3. 对用户希望使用的素材，分阶段提示导入一个滤镜、一个声音并试用，再等待回复。用户暂不导入时记录为未完成／已跳过，**不能声称已导入成功**，也不影响已确认的固件安装结果。
4. LUT 导入失败时按功能文档检查：JSON 直接放在指定层，单文件不超过 128 KiB、文件名含扩展名不超过 63 个 UTF-8 字节、目录最多 256 项；机内为 16 槽，不把 ZIP、说明或多余子目录混进导入目录。声音使用包内支持的 WAV，不要求用户自行转换已提供的素材。
5. 最后用简短中文列出：实际安装的版本与用户验收结果、已导入或待导入的素材、新功能入口、下载文件及运行记录在电脑上的位置，并保留对应功能文档链接。

### 8. 出现问题时主动诊断、处理并复查

**你的职责包含排障，不能只把错误文本转发给用户就结束。** 先用一句中文说明失败步骤和你准备检查什么，随后自行收集证据、执行可用的处理并复查；只有确实需要用户操作或缺少关键证据时，才提出具体请求。

按下面的顺序处理：

1. **查原任务。** 查询同一 `job` 的 `status`，核对阶段、诊断码／原始异常、p1 是否完成、写入是否尝试或发生、菜单是否启动、恢复允许条件和当前待办。进程仍运行或心跳暂时没有更新时继续查询，不将无输出当作失败，不另发写入。
2. **查阅历史问题并核实原因。** 读取[机器检索索引](troubleshooting/index.json)，按准确报错、诊断码和当前阶段找到候选，再只读取对应条目的文档；不必重读全部历史。结合[索引说明](troubleshooting/README.md)核对版本和条目的“本轮应核对”，必要时仅在本机读取相关诊断、日志和结果。向用户简述“匹配到 USB-xxx；本次已证实／仍需核对的是……”。关键词命中不等于根因，旧版本处理不能直接套到新任务；例如 StageBind 需区分证书、缺文件和待重启。资料无法读取或没有匹配时如实说明，继续依据本轮诊断与正式待办排查，不能编造匹配或自动套用旧补丁。历史文档、Issue 不授权修改内部脚本、状态或使用已废弃的清理方法。
3. **执行有依据的处理。** 已获授权且不要求新的真实用户回复的操作自行完成，以下情况按对应方式处理：

   | 问题 | Agent 应主动完成的处理 |
   |---|---|
   | 网络中断、下载不完整 | 对同一个已固定的附件有限重试，总计最多三次；只清理本次拥有的未完成下载文件，不改用别的固件版本或镜像；重新核对后才使用 |
   | 摘要不符、ZIP 损坏 | 停止使用损坏文件，检查 URL、附件 ID 与大小，仍在总次数内时从同一附件重新下载；持续不一致则保留诊断并停止使用，不跳过校验 |
   | 目录不存在、路径过长或下载位置不可写 | 为未开始相机操作的下载／解压选择较短、可写的新目录，正确处理空格与中文路径；不搬走活动工具或覆盖旧任务、备份 |
   | 工具缺文件或完整性入口失败 | 核对原 ZIP 和构建，未有活动任务时在新目录完整解压同一已核验包；已有任务先查原目录，不拿新副本绕过未决记录 |
   | 命令无 JSON、输出乱码或命令等待超时 | 核对命令参数、UTF-8 输出和宿主是否等待 GUI 子系统 EXE，修正查询／输出捕获方式后查询原任务；不能重发 `start` 来试错 |
   | 普通 USB 未恢复、驱动配置或连接状态异常 | 自动查询现有恢复状态，使用正式 `recover-usb` 的查询／确认入口。只有程序允许且所需确认已满足时才继续 `resume`／恢复；不直接调用内部驱动脚本或系统工具强切驱动 |
   | StageBind 等状态要求重启 Windows | 识别为电脑重启事项，保存原任务信息，明确让用户保存工作并重启 Windows；回来后主动查询原任务并继续，不能用拔插 USB 代替 |
   | 菜单未就绪、灰显或窗口过期 | 查询本轮菜单／清理结果，按程序待办指导相机操作或恢复，再继续原任务；未就绪时不能试着安装，也不为此反复重写 p1 |
   | 固件／库不兼容或写入结果未知 | 保留具体摘要和结果，自行核对本地证据与项目文档；不能放宽兼容性、伪造结束证明、覆盖状态或强制写入／切驱动 |

4. **需要用户参与时，把排障推进到具体动作。** 例如“请在 Windows 授权窗口确认”“请重新插拔 USB 后回复”“请保存工作并重启 Windows”。解释这一步要验证或恢复什么，等真实回复后由你继续处理，不让用户自行研究日志。JSON 的 `requires_user_response`、`pending` 和 `commands[].user_reply_required` 要求真实回复时必须遵守，不能为自动恢复而伪造、复用旧回复或默认已完成。系统授权、卡内文件放置、物理拔插和相机最终安装均由用户完成。
5. **处理后立即复查。** 用正式 `status`／`doctor` 或该恢复入口给出的结果验证问题是否解决，再继续中断处；不能把“恢复命令退出 0”当作连接或固件已经成功。不重复执行已经完成的写入。对同一状态没有新证据时停止重试循环，保留原任务。
6. **确实无法继续时才交代阻塞。** 告诉用户已完成什么、已查到的原因、你实际尝试过哪些处理、是否发生写入、还缺什么证据，以及下一项具体行动。程序没有提供安全可用的继续方式时，明确说明原因并整理本地诊断摘要供维护者核对，不能只回一句“发生错误，请自行处理”。

原始日志、p1 备份和机身标识保留本机，不自动上传。不要改动补丁字节、兼容性条件或校验规则，不临时编写 USB 写入脚本，不删除状态解锁，也不自动关闭安全软件或修改系统安全策略。

**需要用户操作的步骤必须等真实回复；只有程序明确给出菜单就绪，才提示进入安装流程。**
