# 修改原理与位置

适用模型：Sony ILCE-7M4，模型标识 `01030081`。以下是已核对布局的修改位置，不是通用固件搜索替换规则。地址均需先核对完整库、ELF 映射、原指令和调用语义。

## 普通 USB 执行入口

Senser/Jiritsu 服务协议提供受认证的通信路径；经已验证的文件加载路径将临时 `libJit.so` 装入服务进程，由初始化函数执行原生工作器。实际执行身份已验证为 EUID 0。Windows 侧为服务通信切换 USBSTOR/WinUSB，结束后恢复 USBSTOR；必要时按提示重新插拔 USB。

读取器、写入器和菜单工作器采用每轮独立任务身份，写入提交仅执行一次。主机结果不明不能自动重发；普通 USB 恢复也必须先确认设备写入已结束。

## p1 更新环境

完整 `/dev/cnflasha1` 为 **25,100,288 字节**，分 **766 块**读取。其 FAT 卷为 **19,377,152 字节**；包内 FAT 成员不能代替整分区备份。修改 `boot/initrd.img` 的 SquashFS 内容后重建容器及 `p1chksum`，保留设备文件、元数据、其他内容和分区尾部。

下表偏移属于解包后的库文件。原始字节与修改字节均按文件中的小端顺序表示。

| 文件／函数 | 文件偏移 | 原字节 | 修改字节 | 语义 |
|---|---:|---|---|---|
| `usr/lib/libsdfileinputupdaterapi.so` / `SignatureVerification::VerifySignature` | `0xABF0` | `fd7bbba9fd030091` | `00008052c0035fd6` | `mov w0,#0; ret`，状态码成功 |
| 同上 / `SDUUDConditionChecker::isVersionOK` | `0x9FD4` | `220440b900008052` | `20008052c0035fd6` | `mov w0,#1; ret`，布尔真 |
| `usr/lib/libupdatercorecommon.so` / `RVchk4PI::chkFirmInfo_before` | `0xD208` | `13008012` | `13008052` | 局部拒绝结果 `w19=-1` 改为 `w19=0` |
| 同上 | `0xD27C` | `f3c39f5a` | `13008052` | 另一局部版本拒绝结果改为成功 |

签名状态 **0** 和版本布尔 **1** 不能混用。强制 `isVersionOK` 返回 0 会拒绝更新。工具还检查调用方和虚表，拒绝未知或混合补丁状态。

官方起点保留官方 `etc/VerificationKey.pem` 和四个原 `verifyKey` 入口；已验证的自定义起点保留其已有公钥及 `verifyKey` 状态。写入上述四处补丁不要求把所有相机的公钥换成作者公钥。

候选从当轮完整备份生成，提交后由独立读取器完整回读。已正确打补丁时可跳过重复写入。日常运行只执行完整性和匹配校验，真实错误处理仍保留。

## 拍摄系统的菜单 RAM 窗口

持久更新器补丁不覆盖正常拍摄系统的菜单预检。需要同时处理两个独立位置：

| 组件 | ELF 相对虚拟地址 | 原字节 → 修改字节 | 语义 |
|---|---:|---|---|
| `libupdaterufp.so` | `0x1F50` | `00c84479` → `00c08052` | 局部比较的机身版本改为 `mov w0,#0x600`，即 6.00 |
| `appFw.so` | `0x265B2C8` | `e3050054` → `2f000014` | 条件 `b.lo` 改为同目标无条件分支，避免因卡版本较旧或相同而禁用更新入口 |

运行地址由当前进程映射计算，不能把相对地址直接作为绝对内存地址。工具先在同一会话完整读取 p1，再核对进程身份、指令锚点及版本编码，修改后回读。600 秒窗口结束且工作器仍存活时恢复原指令；进入更新环境或重启使该会话失效。

这两处修改不持久改写 AP 文件，不修改版本页，不全局关闭电源、USB、串流或存储卡条件。局部版本基准仍为 6.00，已验收自定义目标高于该局部基准；未证明能够降到任意更低版本。

## 目标 DAT 与再次更新

当前相机里的接收端决定此次包是否被接受。仅修改待安装 DAT 内的更新器，不能替代当前接收端补丁。安装完成后，目标包的 p1 又成为下一次更新的接收端；因此目标包也必须保留正确的签名状态和版本布尔语义，才能继续按正常菜单安装官方 6.02。

已验证自定义目标包含作者公钥、四库 `verifyKey` 成功返回以及上述 p1 补丁。四个 `verifyKey` 文件偏移为：`libsdfileinputupdaterapi.so +0xA9A8`、`libupdaterapi.so +0x13324`、`libseninputupdaterapi.so +0x5244`、`libuudfileinputupdaterapi.so +0x95AC`，既有桩均为 `00008052c0035fd6`。这些是该目标包的状态，不是 1.00 软件对用户卡文件所做的修改。

DAT 内保留原官方 256 字节签名，但修改后的内容与该签名不匹配。这里没有生成官方有效签名。兼容性配方见 [patches.json](patches.json)，样本身份及验收范围见 [VALIDATION.md](VALIDATION.md)。
