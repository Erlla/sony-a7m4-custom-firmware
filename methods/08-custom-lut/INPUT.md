# LUT 摇杆与拨轮输入

[English](INPUT.en.md) · [LUT 方法](README.md) · [源码与构建](../../native/custom-lut/input-adapter/README.md)

[Issue #52](https://github.com/Erlla/sony-a7m4-custom-firmware/issues/52) 反馈 LUT 页面出现摇杆与拨轮无法操作、触摸仍可用。先对当前组合 AP 做离线回放，确认普通方向键可用，但摇杆及四组拨轮事件未被处理；补齐输入映射后，维护者于 2026-11-25 确认问题已修复。

## 操作

- 摇杆四方向对应普通方向键，长按方向可重复；中心按下确认。
- 选槽与列表页：拨轮右转向下选择，左转向上选择。
- 微调页：左右键或摇杆左右选择项目，拨轮右转增加、左转减少。
- 触摸、普通方向键、OK 和 MENU 保留原有预览、保存及取消行为。

## 原因与修改位置

同一 AP 的事件名称表及 ELF 重定位把实体输入区分为普通方向键、摇杆和拨轮。原 `lut_native_key`（VA `0x9001074`）只接受普通方向键、确认和 MENU；LUT GUI 入口遗漏了另外两类事件的转换。基线回放能复现“摇杆不动，随后触摸成功”，但没有重建原报告的全部偶发条件。

在已经完成 LUT 页面归属检查的 `0x903104C` 入口，转入 `0x904FC00` 的 368 字节适配器，然后调用原 GUI 分发 `0x903E5E0`。D9 为选择/列表场景，DA 为微调场景；其他场景直接沿用原分发。只调整传入的事件值，不改写借用的消息记录。

| 输入事件 | 转换 |
| --- | --- |
| `02010011/13`、`02010014/16` | 摇杆上/下及重复 → 普通上/下 |
| `02010017/19`、`0201001A/1C` | 摇杆左/右及重复 → 普通左/右 |
| `0201001D` | 摇杆中心按下 → 确认 |
| `02050000/02/04/06` | 四组拨轮右转 → D9 向下、DA 增加 |
| `02050001/03/05/07` | 四组拨轮左转 → D9 向上、DA 减少 |

释放、中心长按重复、斜向及其他未列入的事件保持原值。适配器不新增可写全局状态或堆分配；原预览队列、快速切换合并、异步完成、提交锁、取消及触摸继续由已有 GUI 处理。

## 精确组件与集成

| 项目 | SHA-256 |
| --- | --- |
| 输入 AP | `0cb44d4b8b4a7a9675603de6c10c5e7b4dbeae06e6226566e420f565bff8b1a0` |
| 输出 AP | `db820a263c23e29b15e98057976bc58a6af9c2aa9885709216ea7c2fc8b23666` |

两者均为 99,221,508 字节。输入是[英文资源与快捷键／HEIF 组合](UI-LANGUAGES.md)后的 AP。修改仅为入口 4 字节、适配器 368 字节和既有 RX 段长度字段 16 字节。代码位于语言模块终点 `0x904FBF0` 之后，RX 延长到 `0x904FD70`；其他 AP 字节保持。

按[公开构建命令](../../native/custom-lut/input-adapter/README.md)从源码生成组件；完整布局与差异摘要见 [reference.json](../../native/custom-lut/input-adapter/reference.json)。集成时保留已有 34 个语言库、CP、MPR 和其他文件，再通过既有封装流程同步分区校验。此前独立组件的地址和哈希限制继续保留，不能用旧整份 AP 覆盖当前结果。本方法不修改更新器或签名流程。

## 验证范围

基线 15 组回放确认缺口；修复后 43 组 GUI 回归和两档加载偏移下的 10 项重定位检查通过。覆盖 17 种映射与普通键的完整 GUI 状态/后端请求对照、四组拨轮微调、连续 40 次拨动、确认锁、混合触摸/实体输入、MENU、页面门控和全部 17 个触摸行。

GUI 分发和事务执行实际 AP 指令，绘图、计时器、目录、后端完成及页面退出接收端使用夹具，不能据此声称整机调度或所有外设组合均通过。维护者的确认针对本次输入问题，未附逐项实机测试矩阵。公开构建的输出与已验收 AP 逐字节一致。
