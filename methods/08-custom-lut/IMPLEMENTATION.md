# 自定义 LUT 的修改位置与实现

[功能](README.md) · [精确位置与哈希](reference-layout.json) · [组合方法](INTEGRATION.md)

本方法是新增原生菜单、独立参数库和 AP/CP 颜色接线。不是在原厂菜单中改一个滤镜名称，也不是把通用 RGB LUT 原样交给 ISP。以下符号为自定义源码/分析命名，地址属于已核对布局，不是索尼公开源码接口。

## 修改对象

| 对象 | 修改结果 |
| --- | --- |
| `nflasha15:/lib/appFw.so` | 菜单、D9/DA 原生页面、JSON 解析、16 槽事务存储、八项微调/强度、AP 工作线程与 CP 通信 |
| `nflasha8:/cpapp-b.bin` | 照片/取景颜色代际、原生参数与网格、参数快照、Gamma/任务引用交接、缓存安全复用 |
| 68 个横/竖屏语言资源 | LUT 菜单文字，并保留声音和纵横比的资源记录 |
| 文件系统与镜像封装 | AP 扩展段、文件长度和所在文件系统空间；完整包另外重算分区/容器校验与签名 |

`libmpr.so` 的声音与 JPEG EXIF 修正、`av-cam.bin` 的裁切实现作为既有依赖保留。组件的完整 SHA-256、AP LOAD 和 CP 区间在 JSON 中列出。比较输入已经具有 LUT/声音/纵横比框架；其中增量表描述替换已有 LUT 实现的具体位置，**不是从官方原文件开始的一键补丁配方**。

AP 地址通过所在 `PT_LOAD` 换算文件偏移：`offset = p_offset + VA - p_vaddr`。CP 为 `offset = VA - 0x108000`。不能把两套地址直接写进 DAT。

## AP 菜单与线程

| AP VA | 接线 |
| --- | --- |
| `0x221820C` | 原生页面事件路由 `lut_widget_route` |
| `0x23BA044` | 页面管理器初始化 `lut_widget_manager_init` |
| `0x1840C60` | 应用初始化后缀 `n6_app_init_suffix` |
| `0x35E6244` / `0x35F5508` | 参数与拍摄路径挂钩 |
| `0x351A774` / `0x351A738` | 原生 owner 发送与任务执行 |
| `0x1F0581C` | 全局电源事件恢复 |
| `0x18412BC` | 原生 GUI 循环尾部的受控进度刷新 |
| `0x18C0424` | 导入文件名确认回调 |
| `0x511D680/688`、`0x511D6E0/6E8` | 选择页/编辑页 presenter 与 controller 工厂 |
| `0x50CD498`、`0x50CD1F8` | 原生标尺与文本工厂 |

工厂指针与相应 `R_AARCH64_RELATIVE` addend 必须一起更新。绝对运行地址须加 ELF load bias；独立模块使用 PIC 和固定导出表，不把本地仿真基址当作机内地址。

LUT 控制 RX 位于 `0x09000000`，本布局长 `0xEFF0`；控制 RW 位于 `0x08F73000`，长 53,128 字节。新增后台 RX 位于 `0x09030000`、长度 `0x12E7C`，固定 ABI 导出表位于 `0x09031000`；RW 位于 `0x09050000`，文件 4 字节、内存 160 字节。保留纵横比 RX `0x09010000` 和 RW `0x09020000`。实际程序头表文件偏移为 `0x05E80000`，共 15 项；同时维护 ELF loader 对整个对象跨度的映射。

GUI 只提交请求/显示状态，导入和颜色传输由相应工作线程执行。初次载入的短等待/刷新必须放在已确认的原生线程与 GUI 循环边界，不能在任意事件回调里重入存储或颜色处理。

## “关”页面的按键行为

“关”页面按右键不进入诊断或调节页，正常上下切换、确认关闭与返回保持。GUI 源码不注册 `perf_active = 1` 的右键入口；供精确旧 AP 组件使用的[离线修补工具](../../tools/disable_lut_ram_diagnostics.py)将 `p4_gui_dispatch` 的 `VA 0x903EC48` 从条件分支改为直接跳到正常按键处理 `0x903EA08`。文件偏移为 `0x5E8EC48`，字节 `01eeff54 → 70ffff17`；工具核对完整输入 SHA-256、ELF 映射与输出 SHA-256，拒绝未知组件。

```powershell
python tools/disable_lut_ram_diagnostics.py --input appFw.so --output appFw.no-diagnostics.so
```

这一步只输出 AP 组件。组装固件时还须写回文件系统、更新分区 CRC 并重新封装签名；更新器与 CP 无需改动。组件身份见 [reference-layout.json](reference-layout.json)。

## 八项预览、九项编辑

预览复用原生八项参数显示。详细页保留原生 type `0x5E` 的八个子项，强度单独占第九项；不把原厂固定为八的内部循环改成九。标尺按当前项目切换有符号、无符号或锐度范围模式。

当前橙色高亮仍由原生 type 11 的 No.23 绘制。九个 type 14 触摸矩形 No.80～88 负责切换项目，仅隐藏当前项的白色描边/重复自身命中框，其他八项保留触摸；不隐藏高亮、数值和上下箭头。选中可见性条件为 `p[0x2c] = (i - 80u) != cell`。刷新定时器锚点使用独立文本 No.40，不能绑定到八项复合控件 No.33。删除/清空按钮组按屏幕宽度居中。

每槽保存 `delta[8]` 和强度档位。编辑页显示作者默认值加微调后的有效值，并按对应原生范围限制；确认提交选择和参数，取消恢复进入页面前的快照。强度使用固定 ST 默认数据作为端点，与当前原厂 ST 参数分离；照片和取景分支各自处理系数、矩阵和 Gamma，附加网格以零网格为减弱端点。

## 导入与持久化

SD 目录为 `PRIVATE/M4ROOT/GENERAL/LUT/`，内部存储目录为 `/setting/clut/looks`。扫描、选择和最终读入之间绑定文件身份并重新核对完整哈希。以 UUID、修订和运行内容哈希区分内容；同身份冲突或修订回退不能当成正常替换。16 个用户槽位与内部事务记录、运行缓存是不同的概念。

内部索引使用双副本/代际恢复；先写内容、同步并校验，再发布索引。已提交选择和预览分别持有保护。替换正在使用的内容必须等到确认的安全交接点；导入失败/取消保持先前可用选择，不能只改菜单名称假装完成。开机从机内已提交状态恢复，随后向 CP 传递完整代际；不用 SD 文件作为每次开机的唯一数据源。

## CP 参数快照与缓存回收

LUT 内容保持不可变；参数采用值快照，拍摄任务冻结自己的八项值和强度身份。63 个 bank 用于保存同时驻留的内容，原生使用者释放后可再次使用。

[缓存核心](../../native/custom-lut/cache_core.c)把 ready 与引用数放在同一个原子状态字：发布态为 `1 + 2 * refs`。写者只能取得无引用 bank；读者先 CAS 获取引用，再读 64 位 generation，避免 ARM32 撕裂。陈旧 generation 拒绝获取。所有 bank 仍被占用时返回 BUSY，等待真实引用释放后重试，不能按超时或菜单 Off 强制清零。

| CP VA | 原生生命周期/颜色接线 |
| --- | --- |
| `0x30646A` | 全局颜色对象持有引用的交接 |
| `0x222D34` / `0x222FFE` | 主颜色处理进入/退出 |
| `0x2E22C4` / `0x7A35D6` | tone 与待处理 Gamma 对象 |
| `0xA06262` | 拍摄任务归还时释放该任务引用 |
| `0x3F4A48` / `0x9CFAF8` | 重置与 Gamma 副本交接 |
| `0x69E772/69EA70/69F2FC/6A027A` | 网格副本交接 |
| `0x7D50FA` / `0xA21E3A` | 原生 GFW 复制边界内冻结参数值 |
| `0xA049B0` / `0xA03142` | 保留纵横比冻结/任务复制后，再绑定 LUT 默认值与引用 |
| `0x22533A/225524`、`0x6A4F28/6A4C24` | Gamma、系数和矩阵消费者 |
| `0x22325C` / `0x3D2010` | 原生网格上传与消费边界 |

CP LUT RX 使用 `0x118000..0x11B000`；网格/生命周期代码使用 `0x11C000..0x11D000`，不能覆盖纵横比实际代码 `0x11B000..0x11B67C` 或 BSS `0x11D000`。引用数据与 codec 分别放在 `0x120000..0x126000`、`0x126000..0x128000`。常驻分区和所有细粒度修改见 JSON，不可将整页空余空间视为无主区域。

原生全局颜色、取景、tone、待处理/转换 Gamma、网格副本和照片任务都必须接入引用生命周期。只在菜单层删除缓存不能保证异步任务仍引用的旧数据安全。

## 移植与核对顺序

1. 用完整组件哈希识别布局，确认已有方法占用的空间、钩子、注册器和文字 ID。
2. 实现 JSON 验证与库事务，再连接 AP owner 线程、固定 ABI、CP 代际和原生引用交接。
3. 保留组合调用链，重新链接地址；不要把旧构建的整份 AP/CP 覆盖到新组合上。
4. 检查 ELF/PIC、Thumb 类型、LOAD/重定位、CP 区间、原生回退、微调快照、旧帧保持、BUSY/回收和取消/重启恢复。
5. 完整包独立提取后核对 AP/CP、所有资源和依赖。机内验证菜单、导入/替换、九项调整、关闭恢复、拍摄保存、声音与裁切；色彩转换另做配对测量。

本页和位置清单提供可审阅的方法与结果；可编译缓存核心不等于完整固件的全部源码和构建依赖。
