# 方法 2：自行设置报告的固件版本

[English](README.en.md) · [总说明与刷机风险](../../README.md)

此方法修改相机报告的固件版本，不替换 AP/CP 程序，不改变硬件能力。更改报告值也不保证解除所有降级限制：机型、升级包内部版本、兼容性与验签仍是独立条件。

## 数据位置与 BCD 原理

1. 通过 fastboot 读回本机 `nflasha2` 设置分区。
2. 解析 FAT 目录及簇链，找到 `updater/dat4`。正常内容只有两个字节：**先次版本、后主版本，采用 BCD**。
3. BCD 每个半字节代表一个十进制数字，解码为 `(byte >> 4) * 10 + (byte & 15)`。把十进制整数直接写成二进制会得到错误版本。

| 报告版本 | dat4 原始字节（十六进制） |
|---|---|
| 0.00 | `00 00` |
| 6.02 | `02 06` |
| 6.15 | `15 06` |
| 6.20 | `20 06` |
| 9.99 | `99 09` |

例如旧式二进制写法把 `6.20` 的 20 写成 `0x14`，相机会按 BCD 显示 `6.14`；把 `0x15` 用普通十进制打印又会错误显示 `6.21`。本项目已修正这两个方向。

证据来自 6.02 `libInfraGetVersion.so`：SHA-256 `3a69e737c04b50d120d00e8a0b977f1d60dbb4228abe3b41083e7ab9178be620`，读取入口 ELF VA `0x12F0`，BCD helper `0xDF0`。这里引用的是固件二进制分析，不把人工还原函数称为索尼源码。

## 操作

先阅读备份和 [环境准备](../../docs/setup.md)。入口会先做本次连接的完整备份：

```powershell
python -m a7m4 maintain --action set_version
```

也可双击 `advanced/查看或设置固件版本.bat`。输入留空只查看；输入 `X.YY` 准备改写，当前允许主版本 `0`–`9`、次版本 `00`–`99`。这覆盖当前已验证单数主版本的使用范围，并不宣称固件内所有版本相关字段均能无限扩展。

若只想离线审查自己的备份：

```powershell
python -m a7m4.offline version local/my-backup/nflasha2.bin
python -m a7m4.offline version local/my-backup/nflasha2.bin --set 6.20 --output output/nflasha2-version.bin
```

离线命令不操作相机。实机命令将原版本、目标版本、分区哈希和写入确认文字一起显示；只有准确输入确认文字才写入，随后完整读回核对。所有提示是 UTF-8，BAT 使用 Windows UTF-8 代码页。

## 约束与恢复

- 原数据必须长度为 2、两个字节的各 BCD 位均为 0–9；非法旧编码会中止，不猜测或覆盖。
- 严格限定输入格式，拒绝 `6.2`、`06.02`、负数、命令文本和超出范围的主版本。
- 验证 FAT 副本、目录及簇链，保留分区大小、分配链和其他文件；实际差异只能是 dat4 的 0、1 或 2 个字节。无需为了“恰好改两字节”而附带修改其他数据。
- 恢复可设置为原报告值。若需恢复完整设置分区，使用同机备份并考虑备份后新增设置会被回退。
- 已安装程序的真实基线仍要依据二进制哈希识别，不能依据可自行改写的菜单版本号选补丁。不要为降级而混刷不匹配的 AP/CP、引导程序或校准区。

实现见 [patching.py](../../a7m4/patching.py)，合成 FAT、BCD 边界和无关数据保留测试见 [tests](../../tests)。
