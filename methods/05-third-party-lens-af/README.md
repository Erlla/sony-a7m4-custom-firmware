# 方法 5：副厂镜头能力过滤与对焦速度限制修改

[English](README.en.md) · [刷机风险与备份要求](../../README.md)

**未经测试：去除对焦速度限制的功能尚未经过实机速度、AF 跟踪或连拍收益测试。** 不承诺某支适马/腾龙镜头更快、固定帧率或等同原厂镜头。下面的字节核对和离线原指令回放不构成实机测试。

## 原理：保留镜头自己上报的能力

CP 分类函数 `0x9975D6` 在自动配置下，将部分 ID（最高两位为3、最低12位不为 `0xFFF`）标为兼容类别。之后的 info7/info8/info3D 过滤和能力发布门控会削减镜头已经上报的参数。info3D 处理会清零 packet `+0x2A` 起22字节，影响动态 `MaxFcSpeed` profile 标志；原速度消费者可能因此退到静态表/旧驱动路径。

补丁只让五个指定消费者在“原兼容标志=1 且配置=自动0”时看见0，保留镜头原始能力和速度参数。显式兼容配置、未知配置、未知标志保持原值；全局分类器和其他七处兼容消费者不改。它不制造镜头没有的 AF 能力，不写固定马达速度，不改原最大速度校准、移动时间计算或帧间隔下限。

历史研究使用了 [ExifTool 的 Sony LensType2 表](https://exiftool.org/TagNames/Sony.html) 交叉核对 ID 类别。它不能代替用户具体镜头的实际 ID/能力采样，也不意味着该条件下每支镜头均已测试。

## 精确补丁

目标文件是 `nflasha8:/CPAPP-B.BIN`。此 CP 的常规映射为 `VA = 文件偏移 + 0x108000`。

| CP VA | 文件偏移 | 修改目的 |
|---|---|---|
| `0x3B3CB4` | `0x2ABCB4` | info7 原始镜头信息调用 |
| `0x3B3006` | `0x2AB006` | info8 驱动参数调用 |
| `0x3B321E` | `0x2AB21E` | info3D 扩展 AF 能力/速度 profile 调用 |
| `0x990ADC` | `0x888ADC` | 真实能力位12/15/21发布调用 |
| `0x990BAC` | `0x888BAC` | 真实能力位28/29等发布调用 |
| `0xBA4E00` | `0xA9CE00` | 34字节局部 getter helper |

前五处将原 Thumb BL 改为调用 helper。helper 保存 R1/R2、SP/LR，仅在上述自动类别条件下把返回值置0；原调用后的 CMP/分支继续执行。共 **六处修改，实际差异52字节**。

精确旧/新字节与整文件哈希在 [lens-af.json](../../a7m4/profiles/lens-af.json)，实现见 [features.py](../../a7m4/features.py)。此前改变全局分类器的两字节方案会减少既有 AF 命令，已经否决，未收入公开配方。

## 两种严格绑定的输入

CP 必须是16,236,816字节，且具有已存在的 rodata 可执行映射（文件 `0x4EC` 为 `0F 30 A0 E3`），helper 空间的完整前像为零。

| 输入 | 源 SHA-256 | 补丁后 SHA-256 |
|---|---|---|
| 本仓库已公开 FL2/FL3 v7 CP，源于6.02 | `4551c73386c27a0a9b247fd3e05c3bd5e3425bdb9fe9f8374c201c96533b3479` | `fdf131baa7c951ecf07e14ab47137fd00bbff71301995faf55f2e136b2e0a160` |
| 历史实验6.13 CP | `290e1ccec739ddf9604dc928663c934cb2e04c5976fef32ca35ebe582042380d` | `1c34764fe413d4c0d720d629e323996498305fc29e5c53d2c52d0cca0c0d1504` |

第一行是本次为公开基线重新绑定的**实验配方**：六处前像、已有执行映射和四段相关原代码与历史6.13核对；不把历史6.13完整审核自动当成新基线的完整验证。第二行复现历史6.14/6.15的原功能增量。两者均没有完成实机对焦速度验收。

不接受原厂6.02 CP直接套用，因为其执行布局不同；不提供跳过哈希、任意地址或取消映射检查的参数。镜头方法单独描述能力过滤，输入的既有 FL2/FL3 是受支持文件布局，不是对焦算法依赖滤镜颜色。

## 离线复现与回滚

```powershell
python -m a7m4.features lens-af local/CPAPP-B.BIN --output output/CPAPP-B-lens-af.BIN
python -m a7m4.features lens-af output/CPAPP-B-lens-af.BIN --undo --output output/CPAPP-B-restored.BIN
```

也可从匹配基线的本机完整 nfa8 备份构建 FAT 镜像：

```powershell
python -m a7m4.features lens-af local/my-backup/nflasha8.bin --partition --output output/nflasha8-lens-af.bin
```

脚本核对整文件哈希、映射、六处前像、边界/不重叠、最终哈希及52字节差异；保持 FAT 分配、其他文件与分区长度。它不会连接设备，输出/报告始终标记未经实机测试。

已有方法3的**原始未加本功能**组件时，可在它的 SD 构建命令中显式增加 `--lens-af`。构建器会在核对原 FL2/FL3 组件后应用此独立配方，并将未经测试状态写入 `verification.json`。默认构建不添加本功能。不要把已打镜头补丁的 CP 再传给默认组件入口。

安装必须备份 eMMC 与独立 CP NOR，并建立匹配自签信任。**只 fastboot 写 nfa8 不会同步独立 NOR**；应使用匹配基线的 SD 更新链完成同步，再回读两处 CP 和配置。完整文件构建/安装/回读方法见 [方法3的安装顺序](../03-fl2-fl3/README.md#实机安装顺序)；不要对未知固件直接刷整份历史 CP。回滚也需使 eMMC 与 NOR 的 CP 保持一致。

## 证据与必须保留的状态说明

历史6.13增量有1,216组原/候选回放、52组请求到速度消费者回放、16组未知标志测试，以及98组独立回放/13项检查。输入为合成数据，部分外部 SDK/硬件边界使用替身；合成 profile 数值7000/9000仅验证参数保留，**不是实测速度**。

历史6.15的一般使用反馈“暂未遇到问题”不等于验证了对焦加速。本次没有采样实际镜头 ID、能力快照、速度校准或追焦表现，也没有访问/刷写相机。**发布状态仍为：未经实机测试，效果未知。**
