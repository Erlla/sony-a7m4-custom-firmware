# 方法 5：镜头 AF 机制分析与兼容能力过滤修改

[English](README.en.md) · [刷机风险与备份要求](../../README.md)

**未经测试：去除对焦速度限制的功能尚未经过实机速度、AF 跟踪或连拍收益测试。** 不承诺某支适马/腾龙镜头更快、固定帧率或等同原厂镜头。下面的字节核对和离线原指令回放不构成实机测试。

## 两条独立的 AF 判断机制

已确认一条按数值镜头 ID 触发的兼容能力过滤链，以及另一条按类别、能力和档案决定的 AF 范围门控。**当前补丁只局部解除前者，没有解除后者，也不代表全部 AF 限制都已移除。**

下述地址绑定原版 CP 分析样本：16,236,816 字节，SHA-256 `7b9b137d696e5972d20db7f9119076172ed8e0730805d7f0b4c31b87689e2c2b`，常规映射 `VA = 文件偏移 + 0x108000`。这是分析与回放输入，**不属于后文允许直接打补丁的输入**；这些地址不适用于任意固件版本。

### 机制 1：按镜头 ID 触发兼容能力过滤

CP 的 `0x3B3C88` 处理 info7，通过 `0x98ED0E` 取得响应，然后从响应 `+0x0A/+0x0B` 组合小端 16 位数值 ID。响应处理后复制到镜头记录 `+0x21` 和 `+0x116`，第一份记录中的 ID 位于 `+0x2B/+0x2C`。这里读取的是数值 ID，不是 16 字节镜头名称。

`0x9975D6` 先清零全局兼容标志 `0x14F3774`，再读取配置 `0x104C730+0x17`：配置 1 强制置位；配置 0 执行下式；其他非零配置保持本次初始化的零值。

```c
compatibility = ((lens_id >> 14) == 3)
             && ((lens_id & 0x0FFF) != 0x0FFF);
```

`0x997618` 返回该标志。自动配置的对照 ID `0xC530/0xD123` 置位，`0x8050/0xFFFF` 不置位。原厂类别对照在这条链中保留原始数据，但不能据此推断每支原厂镜头在所有模式下都没有其他约束。

| 数据与阶段 | 原函数 | 已确认行为 |
|---|---|---|
| info7 基础信息 | `0x997624` | 对部分字段做掩码、清零或固定值替换；保留数值 ID |
| info8 驱动参数 | `0x997670` | 对部分上报参数做掩码、清零或兼容值替换 |
| info3D 扩展 AF 信息 | `0x997940` | 能力字 `packet+0x21/+0x22` 与 `0x0C01` 相与，并清除其他字段；从 `packet+0x2A` 起清零 22 字节 |
| info3D 缓存 | `0x3B321E..0x3B3248` | 过滤后响应按尺寸元数据复制到镜头记录 `+0x139`；验证输入为 64 字节 |

因此 packet `+0x21` 对应镜头记录 `+0x15A` 的扩展能力，packet `+0x32` 对应记录 `+0x16B` 的动态速度 profile 支持位 `0x30`。后者落在清零范围内：镜头已经上报的速度档案可能在后续算法使用前失效。

协议支持也有独立判断。`0x3AD130` 除保留必需命令 1 外，将镜头上报的命令位图与兼容掩码或机身普通协议掩码相交。启动窗口 `0x3B31EC` 在缓存的 command3D 支持为 1 时走 `0x3B3762` 请求路径，即使可选 command5A 不支持；没有 3D 支持时仍保留清空扩展记录的回退。因此不能把全局兼容标志当成单一的“AF 限速开关”。

速度消费者 `0x394978 → 0x9579D0` 在其他状态守卫通过后检查记录 `+0x16B & 0x30`：有效则使用动态档案中与驱动频率对应的校准值，否则查询 `0x103F582` 的 53 项静态 ID 表。仍未取得速度参数时，该接口可返回零；后续调度在相应条件下采用旧驱动路径。零值不表示镜头完全不能 AF。原移动时间计算 `0x95A5B0` 及帧间隔下限继续约束驱动，不由本补丁改写。

### 机制 2：按类别、能力和档案决定 AF 范围

入口 `0x47B9FC` 解释镜头描述符，按输入 word `+0x00` 的类别 0..4 分发；类别 1 及大于 4 的值走 `0xA3FFBC` 回退，其他类别有不同能力和版本条件。**类别 1 的上游来源及产品含义尚未完整绑定，不能直接把它命名为“副厂”。**

在已确认的回退分支中：

1. 输入 `+0x14` 被复制到输出 `+0x11`；该输出或输入 `+0x17..+0x1E` 的八项禁止条件任一非零时，清空输出 `+0x10/+0x12/+0x13`。
2. 条件通过后，`0x47E12C` 按类别和数值 ID 查询内置档案。
3. 档案存在时还检查输入 `+0x13`；为零仍清空上述输出标志，通过后才走档案初始化。档案缺失但输入 `+0x15` 报告另一可用路径时，进入对应初始化路径。
4. 档案缺失且 `+0x15` 未置位时，通常在 `0xA40048..0xA40050` 设置 `+0x10=1,+0x12=1,+0x13=1`，形成中心范围状态；ID `0x8010` 另保留输入 `+0x13` 的例外检查。

正常发布链 `0xA3FD3C` 将结果 `+0x10/+0x12` 交给注册的 setter `0x941DD6`，存为 `0x14F1193/0x14F1194`。消费函数 `0x91D12A` 在第一字节为 1 时，按第二字节是否为零返回范围分类 2 或 1；第一字节不为 1 时返回 0。消费者之一可在分类 1 时进入 `CenterOnlyLens` 分支并拒绝相应 Scanless 路径。这组状态不等同于所有 AF 功能的总开关。

另一个 `this lens is not permitted` 路径也不能直接解释成品牌白名单：`0x132E32` 先检查特殊 ID `0x8051/0x8019`，否则检查镜头记录 `+0x4E` 低四位是否为 4；通用协议条件满足仍可获准。仅删除错误提示不能代替协议和能力判定。

**本仓库没有发布 AF 范围门控的解除配方。** 缺档案回退可能涉及校准需求；现有证据不能把每次回退都归因于副厂政策，也没有绑定用户镜头实际走过这一分支。

### 名称查表与上述两条机制的关系

内置档案可以提供 `VX…` 参数文件键。例如原函数 `0x47E12C(category=1, ID=0x8011)` 返回 CP 内部 `0xD46734` 的 `VX9101` 字符串。随后名称查找函数 `0x47B444` 最多比较 16 字节，遇 NUL 提前结束，以选择参数数据；未命中返回失败。已追到的名称来自内置档案，不能据此断言机身直接读取镜头的 16 字节名称做品牌准入校验，也不能把名称查找失败与另一 AF 分支的档案缺失回退混为一谈。

### 当前补丁覆盖范围

补丁只让五个指定消费者在“原兼容标志=1 且配置=自动0”时看见0，保留镜头原始能力和速度参数。显式兼容配置、未知配置、未知标志保持原 getter 返回值；全局分类器和其他七处兼容消费者不改。它不制造镜头没有的 AF 能力，不写固定马达速度，不改原最大速度校准、移动时间计算或帧间隔下限，也不改上述 AF 范围门控。

解除过滤是否改善实际表现，取决于镜头是否触发分类、是否上报有效能力和速度档案，以及是否受到其他工作模式约束。上述链条没有证明 AE 自动曝光限制，也没有完成某支镜头的实机加速验收。

历史研究使用了 [ExifTool 的 Sony LensType2 表](https://exiftool.org/TagNames/Sony.html) 交叉核对 ID 类别。它不能代替用户具体镜头的实际 ID/能力采样，也不意味着该条件下每支镜头均已测试。

## 原版流程的离线复现

[回放脚本](../../tools/replay_lens_af_flow.py)与[原始结果 JSON](native-flow-results.json)公开 16 组有界原生指令回放：5 组 info7 读取/分类/过滤，6 组 3D 支持/请求/过滤/复制/速度选择，4 组范围回退/消费，以及 1 组数值 ID 到内置名称的查询。原版 CP 必须由使用者自行取得，文件哈希必须与本页分析样本完全一致。

研究复现额外需要 Unicorn 2.1.4；它不是 fastboot 主机工具的必需依赖：

```powershell
python -m pip install unicorn==2.1.4
python tools/replay_lens_af_flow.py --cp local/CPAPP-B-stock.BIN --report local/lens-af-flow.json
```

脚本拒绝错误输入及覆盖已有报告，只在模拟器中运行。在明确合成的协议记录、命令支持缓存、尺寸表、工作模式、频率和校准值下，3D 组执行原尺寸读取、memcpy/memclr 和速度消费者，没有 SDK 函数桩；info7 的取包边界和范围 setter 的日志使用显式替身。范围结果到 setter 的两参数传递是显式桥接，没有回放完整的回调注册/分发；类别 1 也是测试输入。名称组只验证内置键来源，没有执行 `lensfile.bin` 传输。

在相同合成扩展能力 `0x30209000`、速度标志 `0x30` 和校准输入下，自动类别 `0xC530/0xD123` 被原版过滤为零，速度接口返回 `[0,0]`；`0x8050/0xFFFF` 对照保留上报字段并选择 `[7000,9000]`。7000/9000 只是输入 fixture 的值，不是测得的速度。原版流程回放也不代替后文精确补丁及各输入基线的验证。

## 精确补丁

目标文件是 `nflasha8:/CPAPP-B.BIN`。此 CP 的常规映射为 `VA = 文件偏移 + 0x108000`。

| CP VA | 文件偏移 | 修改目的 |
|---|---|---|
| `0x3B3CB4` | `0x2ABCB4` | info7 原始镜头信息调用 |
| `0x3B3006` | `0x2AB006` | info8 驱动参数调用 |
| `0x3B321E` | `0x2AB21E` | info3D 扩展 AF 能力/速度 profile 调用 |
| `0x990ADC` | `0x888ADC` | 真实能力位12/15/21发布调用 |
| `0x990BAC` | `0x888BAC` | 真实能力位28/29等发布调用 |
| `0xBA4E00` | `0xA9CE00` | 34字节局部 getter helper |

前五处将原 Thumb BL 改为调用 helper。helper 保存 R1/R2、SP/LR，仅在上述自动类别条件下把返回值置0；原调用后的 CMP/分支继续执行。共 **六处修改，实际差异52字节**。

精确旧/新字节与整文件哈希在 [lens-af.json](../../a7m4/profiles/lens-af.json)，实现见 [features.py](../../a7m4/features.py)。此前改变全局分类器的两字节方案会减少既有 AF 命令，已经否决，未收入公开配方。

## 两种严格绑定的输入

CP 必须是16,236,816字节，且具有已存在的 rodata 可执行映射（文件 `0x4EC` 为 `0F 30 A0 E3`），helper 空间的完整前像为零。

| 输入 | 源 SHA-256 | 补丁后 SHA-256 |
|---|---|---|
| 本仓库已公开 FL2/FL3 v7 CP，源于6.02 | `4551c73386c27a0a9b247fd3e05c3bd5e3425bdb9fe9f8374c201c96533b3479` | `fdf131baa7c951ecf07e14ab47137fd00bbff71301995faf55f2e136b2e0a160` |
| 历史实验6.13 CP | `290e1ccec739ddf9604dc928663c934cb2e04c5976fef32ca35ebe582042380d` | `1c34764fe413d4c0d720d629e323996498305fc29e5c53d2c52d0cca0c0d1504` |

第一行是本次为公开基线重新绑定的**实验配方**：六处前像、已有执行映射和四段相关原代码与历史6.13核对；不把历史6.13完整审核自动当成新基线的完整验证。第二行复现历史6.14/6.15的原功能增量。两者均没有完成实机对焦速度验收。

不接受原厂6.02 CP直接套用，因为其执行布局不同；不提供跳过哈希、任意地址或取消映射检查的参数。镜头方法单独描述能力过滤，输入的既有 FL2/FL3 是受支持文件布局，不是对焦算法依赖滤镜颜色。

## 离线复现与回滚

```powershell
python -m a7m4.features lens-af local/CPAPP-B.BIN --output output/CPAPP-B-lens-af.BIN
python -m a7m4.features lens-af output/CPAPP-B-lens-af.BIN --undo --output output/CPAPP-B-restored.BIN
```

也可从匹配基线的本机完整 nfa8 备份构建 FAT 镜像：

```powershell
python -m a7m4.features lens-af local/my-backup/nflasha8.bin --partition --output output/nflasha8-lens-af.bin
```

脚本核对整文件哈希、映射、六处前像、边界/不重叠、最终哈希及52字节差异；保持 FAT 分配、其他文件与分区长度。它不会连接设备，输出/报告始终标记未经实机测试。

已有方法3的**原始未加本功能**组件时，可在它的 SD 构建命令中显式增加 `--lens-af`。构建器会在核对原 FL2/FL3 组件后应用此独立配方，并将未经测试状态写入 `verification.json`。默认构建不添加本功能。不要把已打镜头补丁的 CP 再传给默认组件入口。

安装必须备份 eMMC 与独立 CP NOR，并建立匹配自签信任。**只 fastboot 写 nfa8 不会同步独立 NOR**；应使用匹配基线的 SD 更新链完成同步，再回读两处 CP 和配置。完整文件构建/安装/回读方法见 [方法3的安装顺序](../03-fl2-fl3/README.md#实机安装顺序)；不要对未知固件直接刷整份历史 CP。回滚也需使 eMMC 与 NOR 的 CP 保持一致。

## 证据与必须保留的状态说明

历史6.13增量有1,216组原/候选回放、52组请求到速度消费者回放、16组未知标志测试，以及98组独立回放/13项检查。输入为合成数据，部分外部 SDK/硬件边界使用替身；合成 profile 数值7000/9000仅验证参数保留，**不是实测速度**。

历史6.15的一般使用反馈“暂未遇到问题”不等于验证了对焦加速。本次没有采样实际镜头 ID、能力快照、速度校准或追焦表现，也没有访问/刷写相机。**发布状态仍为：未经实机测试，效果未知。**
