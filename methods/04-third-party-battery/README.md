# 方法 4：去除副厂电池的电量显示与提示限制

[English](README.en.md) · [刷机风险与备份要求](../../README.md)

公开范围是 AP 中两类本地策略：让能够上报电量的副厂电池显示真实百分比，以及跳过“副厂电池继续使用”提示。**不是修改电池认证算法或保证所有副厂电池可用**；充电、温度、低电量关机保护和通讯协议不在补丁范围内。

## 原理与精确修改

目标文件为 `nflasha15:/lib/appFw.so`。在已核验的 6.02 ELF 上，以下 VA 与文件偏移相同：

| 路径 | 地址 | 修改 |
|---|---|---|
| 使用中电池百分比 | `0x241A238`、`0x241A2C8` | 本地认证 NG 读取改为 `mov w21,#0` |
| 副电池百分比 | `0x241A488`、`0x241A4F4` | 本地 NG 读取改为 `mov w21,#0` |
| 汇总电量显示 | `0x241A758`、`0x241A760`、`0x241A77C`、`0x241A7E0`、`0x241A844`、`0x241A940`、`0x241A950` | 本地 NG 读取改为 `mov w0,#0` |
| 汇总电量显示 | `0x241A784` | 本地 NG 读取改为 `mov w1,#0` |
| 使用中/副电池提示 | `0x1BAE40C`、`0x1BAE480` | 本地 accepted 读取改为 `mov w0,#1` |
| 启动提示 | `0x2108814`、`0x2108CD0` | 分别改为 `mov w28,#1`、`mov w27,#1` |

电量修改只让这些显示路径把本地 NG 条件看成 0，不改认证源属性、setter 或电池上报值。百分比仍来自电池通讯，无法让本来不提供电量的电池凭空上报百分比。

提示修改让四个本地判断把 `is_3rd_party_battery_caution_accepted` 看成已确认，避免请求资源 `0x462`。全局 accepted 属性和真实认证结果保持。共 **16 条指令，覆盖 64 字节、实际差异 60 字节**；其中显示 48 字节、提示 12 字节。精确前像、新字节及源/目标哈希见 [battery.json](../../a7m4/profiles/battery.json)，代码见 [features.py](../../a7m4/features.py)。

## 支持的输入

仅接受 98,212,632 字节、完整 SHA-256 匹配的 AP：

| 输入基线 | 源 SHA-256 | 补丁后 SHA-256 |
|---|---|---|
| A7M4 官方 6.02 AP | `1e1b9202eaa69198f20df03dbfdab2f103b206cc4ebcd2e7bd817e6a710018a2` | `6fb340604f6dc1a2abb8dbd208e3e380d3789f2756d7abde0f521fdeb49f6920` |
| 本仓库 FL2/FL3 AP | `d17e61fb4ba193d8e7d802196edff5f578d5691b3fcc4abcd1cbbb6e58bdd8ff` | `6aad5c6400170365523c1737404053f53c05b89734a89e5fda734dde5eff7e2a` |

电池补丁本身不依赖 FL2/FL3。第二个输入只是允许在已公开滤镜 AP 上保持既有改动。其他实验 AP、已打过补丁的 AP 或仅菜单版本相同的文件均拒绝；不要整份替换成另一机身的程序/分区来绕过检查。

## 独立离线复现与恢复

```powershell
python -m a7m4.features battery local/appFw.so --output output/appFw-battery.so
python -m a7m4.features battery output/appFw-battery.so --undo --output output/appFw-restored.so
```

程序核对整文件身份、全部前像、范围/重叠、最终完整哈希和实际变化数，拒绝覆盖已有输出。`--undo` 只接受已知补丁后的完整文件，精确恢复对应原输入。

也可基于**本机新鲜完整 nfa15 备份**构建保持原分区长度的镜像：

```powershell
python -m pip install -e ".[firmware]"
python -m a7m4.features battery local/my-backup/nflasha15.bin --partition --output output/nflasha15-battery.bin
```

它解析 ext 文件系统，只替换同长度 `lib/appFw.so` 的实际 extent，并重新打开文件校验。不会改 CP、内核、其他 AP 文件或校准；输出仍是你本机完整分区的长度。**离线命令不会连接或刷写相机。**

刷入前完成 README 要求的备份和线序核对。熟悉外部 fastboot 的用户可对自己生成的完整镜像执行 `fastboot flash nflasha15 <镜像>`，然后重新完整备份并核对 nfa15 SHA-256。直接使用外部 fastboot 不经过本仓库菜单的确认保护。读回不符时应保留恢复入口，不继续启动。不要把 SD 包内较短的成员镜像当成完整分区镜像。

已有方法 3 的原始 FL2/FL3 组件时，也可在其 SD 构建命令上显式增加 `--battery`，由同一配方合并到包中。默认 `build-fl23` 不添加电池补丁；这个组合示例不是单独电池包。不要把已经打过电池补丁的组件再传入默认组件入口。

## 验证状态

历史显示方案有 4,800 组合、14,400 次原指令回放，提示方案有 64 组局部回放；使用合成输入和明确的外部函数替身，不是完整相机仿真。历史用户反馈电量显示正常，但没有回读运行 AP 哈希；新提示移除没有单独完成实机验收。后续组合固件的一般使用反馈也不能替代握柄、热插拔、冷启动和各型号电池验收。

本次公开配方重新核对字节与历史候选一致；没有访问设备。对电池安全和实际兼容性的判断仍需独立实测，保留原有保护不等于保证任意电池安全。
