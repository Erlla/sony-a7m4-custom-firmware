# 自定义电子快门声与自定义对焦声

[English](README.en.md) · [源码、地址与修改方法](IMPLEMENTATION.md) · [可编译原生源码](../../native/custom-sounds/README.md)

在“拍摄 → 快门/静音”增加两个独立声音功能。原厂电子快门没有提示音，本功能在电子曝光事件上新增播放；对焦声则接入原厂合焦提示链。**这不是固件版本修改功能**：不读取或写入 `updater/dat4`，不要求某个内部版本标签，也不在本方法中指定发布版本。二进制兼容性完全取决于源文件 SHA-256、地址布局和调用合同。

本仓库提供原创 C/汇编源码、六模块可复现编译计划、带前后哈希的离线文件配方及验证说明。**参考配方的 AP 输入已经具有共享菜单框架，不是原厂 AP；目前没有自动合入 `a7m4.firmware build-sd` 的开关。** 本方法输出 AP、CP 和资源文件，不输出可直接安装的完整 DAT。先读主项目的[备份与更新要求](../../README.md)，再做完整包集成。

## 功能与操作

| 项目 | 行为 |
|---|---|
| 自定义电子快门声 | 开关、从 SD 卡内导入、音量三个选项；电子曝光按照片身份去重后播放所选声音 |
| 自定义对焦声音 | 开关、从 SD 卡内导入、音量；AF-S / AF-A 合焦替换提示音，可恢复“默认” |
| 音频文件 | 卡内 `PRIVATE/SONY/PRO/SOUNDS/`，两个槽各保存一个 WAV；不把多个 WAV 拼接成播放列表 |
| 导入界面 | 文件名、同步移动的橙色选框、音频专用确认提示；不显示日期或音频时长列 |
| 开关关闭 | 导入和音量行灰色；开关/子项状态在异步提交完成后自动刷新 |
| 文件名 | 导入并持久保存成功后，父菜单显示所选名称；失败不假装保存成功 |
| 关机保存 | 音频字节、文件名、两个开关和音量持久保存；开机恢复后重新建立原生播放资源 |
| 音量 | 10%–100%，每档 10%；50% 是本功能基准增益，100% 为该基准的两倍数字幅度 |
| 静音模式 | 静音优先，两个自定义声音均不播放；解除静音后按原有选择恢复 |
| 机械快门 / 电子前帘 | 不播放电子快门音；切换到非电子快门时排队持久关闭电子声音开关 |
| 默认对焦 | 原厂提示音链保留；关闭自定义对焦或选择“默认”后按原厂声音设置运行 |

建议使用短促的 PCM WAV。解析器接受整数 PCM 格式 1、单声道或双声道、8/16/24/32 位、8–192 kHz，单文件最大 1 MiB、最长 5 秒。压缩 WAV、浮点 WAV、错误 RIFF 长度、不完整帧、越界 chunk 和不安全文件名会被拒绝。仓库附带用户授权公开的 [YEAH.WAV、DAGOU.WAV 和 JIAO.WAV 示例](../../examples/custom-sounds/README.md)，供参考与导入测试；也可自行提供符合格式的音频。示例说明包含 SD 卡目录、操作方法、音频参数及 SHA-256 校验值。

AF-C 不替换为自定义对焦音，MF 不产生合焦提示。原厂“音频信号/对焦提示音”关闭时，自定义对焦也不出声。拍照同时合焦可能连续触发两类事件，区分测试应采用“AF-S 只半按”与“MF 独立拍照”。

## 离线生成修改后的文件

先查看所有 71 个精确输入哈希：

```powershell
python -m a7m4.custom_sound inspect
```

参考 AP 的输入 SHA-256 为 `28bd97605c5cb2e0b9edfeec36abf2dec64a46a9895f79b00c7f9356ce2482c3`，CP 为 `1c34764fe413d4c0d720d629e323996498305fc29e5c53d2c52d0cca0c0d1504`。AP 已包含声音功能使用的共享菜单框架；同名文件、相近版本号或原厂 AP 都不能替代这个前提。其余原始库和语言资源的哈希也逐文件校验，不依据目录名猜测兼容性。

用户自行提供这些合法取得的本地文件：

```text
local/sound-input/appFw.so           # 精确参考 AP
local/sound-input/cpapp-b.bin         # 精确参考 CP
local/sound-input/fs/lib/libmpr.so
local/sound-input/fs/share/app/*.uxc  # 配方要求的 68 个原始语言资源
```

```powershell
python -m a7m4.custom_sound apply --ap local/sound-input/appFw.so --cp local/sound-input/cpapp-b.bin --fs-root local/sound-input/fs --output output/custom-sounds
```

程序先验证全部输入和目标哈希，再新建输出目录；不覆盖输入或已有输出，不连接相机、不枚举 SD 盘符、不执行刷写。结果为：

```text
output/custom-sounds/fs/lib/appFw.so
output/custom-sounds/fs/lib/libmpr.so
output/custom-sounds/fs/share/app/*.uxc
output/custom-sounds/cp/cpapp-b.bin
output/custom-sounds/manifest.json
```

配方采用原文件区间 COPY＋新增字节 ADD，只分发改动配方，不附带完整索尼程序或语言库。完整源哈希与输出哈希均需通过，不能关闭检查后给其他布局套地址。

## 修改其他基线与完整固件集成

1. 提取自己的 AP、CP、`libmpr.so` 和语言资源，记录哈希。先定位 [IMPLEMENTATION.md](IMPLEMENTATION.md) 中的原函数、布局、菜单 ID、ELF 相对重定位及冷启动清零范围；不通过改机身版本号来“适配”。
2. 使用[原生编译计划](../../native/custom-sounds/README.md)编译 AP 与 CP 组件，按导出符号重新生成入口跳板和菜单回调。对不同地址布局重做调用约定、空间归属和原生回放检查；不能只替换一份 C 文件后复制原地址。
3. 将 AP、MPR、全部语言资源作为同一文件系统变更集；把 CP 加入对应程序镜像。完整包需重新计算各层长度、文件/分区校验、压缩文件系统及签名，并检查允许范围外字节保持。
4. CP 必须按项目已验证的 SD 更新链同步 eMMC 镜像与独立 NOR。仅 `fastboot flash` eMMC 中的 CP 镜像不等于更新独立 NOR。不要把本方法的 `cpapp-b.bin` 当成可直接刷入整个分区的镜像。
5. 发布版本由实际完整固件的统一打包步骤管理，本声音方法不改号，也不会自动设置某个内部测试编号。回滚应使用保留的同基线原始文件和本机备份，不能把声音补丁逆套到含其他更改的未知文件。

## 验证范围

维护者单台 A7M4 的既有功能构建经过用户实际听音、相同音量与重复正常关机重启反馈，之后用户确认“所需功能均正常”。公开文件配方完成了离线原生扫描/导入/保存和播放回归，尚未另行取得机内验收。不能据此宣称所有机身、所有模式或任意新组合固件均已通过。

本次公开整理重新验证：六个源码模块的编译及最终安装段、71 个目标文件的完整 SHA-256、32 项 C 核心检查和 Python 拒绝路径/输出保护测试；详见[公开验证记录](../../docs/custom-sounds-validation.json)。没有操作设备或生成新安装包。

完整集成后的机内验证至少包括：独立 AF-S / AF-A 合焦、MF 电子单拍与实际连拍、两个不同音频槽、相同音频及音量档位、默认对焦回退、静音、机械/前帘联动、开机立即操作和多次 OFF→ON、照片保存与正常关机。队列有界，资源未就绪时优先保留原厂回退/拍摄进程，不保证启动后第一瞬间所有音效都已可用。
